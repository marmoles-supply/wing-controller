# WING CONTROLLER Desktop v1.2.17

Build: 20260921.4 (macOS Apple Silicon)
Date: 2026-09-21

## Fixed: the detached Meter Bridge window was not working

The window opened and looked alive, then reported no frames and never showed level.
The cause was in the Tauri permission model, not in the metering itself.

Tauri v2 grants nothing to a window that no capability lists: *"If a webview or its
window is not matching any capability then it has no access to the IPC layer at
all."* `capabilities/default.json` listed only `main`, so the detached `meters`
window could not subscribe to events — no meter frames, no stream status — and its
watchlist never reached the backend.

- The capability now covers `main` and `meters`.
- It also grants `core:window:allow-set-always-on-top`, `allow-set-position` and
  `allow-set-size`. `core:window:default` only grants read access, so **Pin** and
  the saved window geometry would have kept failing after the first fix.
- Closing the window from its right-click menu now uses the real command instead of
  `window.close()`, which does nothing for a window the application owns.

A test now guards this class of failure: `scripts/test-desktop-ui-contracts.mjs`
reads every window label the Rust side creates and fails if no capability matches
it, and it checks that the window permissions the Meter Bridge calls are granted.

## Changed: one Popout button instead of two

The Meters card had two buttons doing the same thing, in the header and in the
toolbar, with different labels. The toolbar duplicate is gone and the remaining
button is called **Popout**, switching to **Focus** while the window is open. The
master bar keeps its **Meters** button.

## Validation boundary

Metering, protocol paths and the read-only hardware checks from 1.2.16 are
unchanged. The detached window path was fixed from the permission model and the
contract test; it has not yet been exercised on a console by an operator, so please
confirm that the window now shows level and that Pin works.
