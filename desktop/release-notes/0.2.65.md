# WING CONTROLLER Desktop v0.2.65

Build: 20261002.2 (macOS Apple Silicon)
Date: 2026-10-02

Four changes: two fixes, a tribute, and the release checks.

## A quiet meter stream is not a dead link

If no **meter frames** arrived within three and a half seconds, the stream tore the whole session down —
even while the console was answering identity probes and OSC state perfectly. The console can send no
meters for entirely good reasons (the group it was asked for is empty, or the subscription was refused),
and saying "disconnected" then did two bad things at once: the operator was told his live console was gone,
and every console write was refused — correctly, because the application had just declared there was no
session. He had to disconnect and connect again from the top bar to get his macro back.

The session now survives a meter stall while **anything** is still arriving from the console: it says so
in the status (`connected; no meter frames for N s — asking the console again`), asks for the meters again
and keeps the session. Only total silence ends it, as before. The rule is a small pure function with its own
test, so it cannot be quietly inverted again.

## The icon: the caches, not the artwork

The custom icon's artwork and its resource fork were both correct, and the Dock still showed the system's
dark tile. The Dock and LaunchServices cache an icon per bundle path and do not re-read it just because the
bundle changed — which is why the DMG's own unblock command worked: it re-applies the icon and then *opens*
the application. `set-custom-icon.sh` now re-registers the bundle with LaunchServices and restarts the Dock
and the Finder as part of applying the icon, and it says plainly that an application which was running when
the icon was applied has to be quit and opened again (the window server reads the icon at launch).

## The credits

The About tab and the shipped guide now thank two people properly rather than citing them:
**Patrick-Gilles Maillot**, who went to the trouble of finding out what these consoles say, wrote it
down and made it public (x32ram.com); and **David Schumann**, who has spent years making Mixing Station
the control surface the people at the desk deserve (mixingstation.app). Without them, this application
would not exist. The Meter Bridge thanks **Maillot alone**, deliberately: the metering that window shows
— the request frame, the report ids, the 1/256 dB scale — is his throughout.

## The Settings window, reachable from the other window again

A theme change made in the Meter Bridge threw a `ReferenceError` in the dock: the `storage` listener lives
with the floating-window controls, outside the Settings closure, and it called a function defined inside
that closure. The Settings boxes then kept the old state. The closure hands its own function to a top-level
holder now — the same pattern this project had already written down for the peak-hold controls — and the
settings suite reports page exceptions by name instead of a bare "Uncaught".

## And the release checks no longer cry wolf about volumes

Three stale mounted images — from 0.2.37, 0.2.40 and the previous verification's own 0.2.63 — made a good
release look red. `verify-install.sh` starts by detaching whatever an earlier run left mounted and names it,
and `build-dist.sh` reports a detach it cannot complete instead of swallowing the failure of all three of
its attempts.
