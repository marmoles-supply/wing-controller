# WING CONTROLLER Desktop v0.2.70

Build: 20261003.2 (macOS Apple Silicon)
Date: 2026-10-03

This release adds the two things that were asked for over the last days: **talking to other applications** (MIDI and
OSC) and **timecode**. Everything is **off by default**. With nothing switched on, this version behaves exactly like
0.2.69 — the full gate and the five-minute soak were run with the feature off to confirm it, and the frame interval
did not move.

## Talking to other applications

- **MIDI**: virtual ports that exist only while the feature is switched on, a monitor, sending, All Sound Off and
  All Notes Off on every channel from PANIC STOP, a macro step that sends MIDI, triggers with **Learn**, and
  conditions on another application's values that can tell "never received" from "received and false" and refuse to
  fire on a stale one.
- **OSC**: a listener that counts what arrives and can fire macros, sending with the address rules the research
  corrected, triggers with OSC patterns, and conditions on the message's own arguments.
- **The applications list** is shared by both: for OSC it is also the allow-list, applied while the listener is
  running. The listener starts on **this machine only**; opening it to the network is a deliberate choice, and it is
  refused unless at least one application is listed, because on a network any device could fire a macro.

## Timecode

- **MTC** arrives through the MIDI port, so it needs no new device and no new permission.
- **Cues**: a position that fires a macro once when the show plays into it, re-arms when the show goes back past it,
  and **names** the cues a seek skipped instead of firing them. The list is saved as it changes and is protected by
  the padlock, because where a cue goes is part of what the show will do.
- **LTC** — timecode recorded as an audio signal — from a **file** and from an **audio input**. The codec is proved
  by generating LTC in its own tests, which is how it was built before any microphone was involved.
- **A clock window** for a second screen (with a pin), and a compact readout in the status area that appears only
  once a position has arrived.

## A review of the work, and what it found

Eight defects were found and fixed before this build. Two of them are worth naming because no test in this tree
could have caught them: macOS **terminates** a process that records audio without a usage description in its bundle,
so this feature would have killed the installed application the first time somebody pressed Listen; and the master
switch refused to start anything new but **did not stop what was already running**, which meant a microphone left
recording kept recording. Both are fixed, and two new checks in the gate keep them fixed.

## What has not been verified

The audio input's live path has never seen a real signal, the microphone permission has never been asked for at
runtime, the acceptance pass with Mixing Station has not been run, RTP-MIDI has been researched rather than
connected, and no real OSC sender has been pointed at the listener. The procedure for the desk is
`docs/MIDI_ACCEPTANCE_STEPS.md`, and the honest state of the whole feature is
`docs/INTER_APP_REVIEW_2026-10-03.md`.
