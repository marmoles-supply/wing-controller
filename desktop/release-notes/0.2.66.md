# WING CONTROLLER Desktop v0.2.66

Build: 20261002.3 (macOS Apple Silicon)
Date: 2026-10-02

This build is the appearance work plus the findings of five audits run over the tree in the same session —
the UI, the Rust backend, the verification suite itself, a visual pass over both themes, and the shipped
documents.

## The app no longer tells a live session that it stopped

The backend recorded a stream's terminal status without checking **which session** it came from. A stream
that has just been replaced still emits once, and its last "stopped" could land after the new session had
said "live" — so the application believed there was no session while the meters flowed. The badge said
Live, the grid moved, and Shoot, Test Action, Fire Macro and the raw send were all refused with
"Not connected (stopped)". Reconnecting during a live session (saving the macro library does it) was enough
to trigger it, and the cure was to disconnect and connect again. Every status now carries the session that
emitted it and a superseded stream is ignored.

## A dead meter link is re-established

If the meter **TCP** connection goes away — the console restarts its meter service, a report id times out, an
access point drops the flow — the desk stops sending meters. The application printed "connected; no meter
frames for N s — asking the console again" while nothing was asked and no socket existed, kept the badge
Live, and left every meter-triggered macro dead for the rest of the session. It now reconnects, drops a
socket whose write fails, and only says it asked when the request really left.

## PANIC STOP, both halves

`raise_every_stop` returned early if the stream-stop lock was poisoned, before cancelling the Shoot in
flight: an emergency stop could report an error while a fade or delay went on writing. Both halves run now
and the first error is returned afterwards.

## A gate that cannot book a run that did not happen

Eighteen of twenty-two browser suites printed "skipped" and exited 0 when the browser was wedged or absent,
and the gate printed PASS — the UI layer could go untested on a green build. Every browser suite now ends
with a completion seal, the gate demands it, a machine without a usable browser fails instead of quietly
skipping the layer, and a passing step's own "skipped"/"not landed" lines are shown beside its PASS rather
than discarded. A failure shows its first lines (the Maillot audit prints its findings before its summary)
and keeps the full output in a log. The strict Maillot audit additionally refuses to pass on an empty
inspection, and the four Rust tests that used to pass by returning early without their `LIVE_WING_*`
variable are ignored with the reason named.

## Stealth Dark, and the things that were never defined

Eight names were used in the dock's stylesheet and defined nowhere, so their light fallbacks won in the dark
theme: text fields were white, the About product name was navy on the dark face (a contrast of 1.06:1) and
`UNSAVED` was maroon. The Meter Bridge had the same problem with three of its own names, and its pressed
matrix button lost its inset shadow. All are defined per theme now.

The Inspector also threw on every action-step hover: it called a `modeLabel()` that did not exist anywhere,
so the hint balloon never appeared for a real step.

## And the smaller truths

The Meter Bridge's pin button and remembered preference moved before an awaited call that could fail — the
button read "Pinned" over an unpinned window, and the lie survived relaunches. The dock's browser fallback
marked the bridge open even when the browser refused to open it, and its reconciler threw its own failure
away. The console address had five writers, one of which disagreed about the empty string, so clearing it
brought the old address back on the next launch. The meter Size preset never followed the Zoom slider.

## The window background

**Settings → General → Appearance → Window background**, or **right-click the background itself**: follow
the theme, the light gradient, the dark gradient, or a flat colour — black, white, grey or any colour
through the picker. A flat colour is flat (the pattern and its texture step aside), both windows read the
same keys, and both ways of setting it go through one function so they cannot disagree.
