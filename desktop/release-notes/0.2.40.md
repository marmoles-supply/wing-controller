# WING CONTROLLER Desktop v0.2.40

Build: 20260922.13 (macOS Apple Silicon)
Date: 2026-09-22

Three UI improvements and one bug fix.

## Diagnostics: OSC monitor first, and every block collapses on its own

- The **OSC monitor now sits at the top** of the Diagnostics card, above the link/health grid and the
  log, which is where an operator looks first when something is wrong.
- **Each block has its own chevron**: the OSC monitor, the link/health grid and the log collapse and
  expand independently, and the state is remembered between sessions (`wing_diag_collapsed`).
- The OSC block **keeps its header when collapsed** (that is where the chevron, the live badge, Ping and
  Clear live), so it can always be opened again.

## Live Meters: "Only meters" focus mode

A button in the Live Meters header hides the rest of the window and leaves that card at full width: the
builder column, the seam and every other card in the column go away, and the layout collapses to a
single column. **Escape** brings everything back (unless it is closing a dialog or a menu), the button
shows its state (*Only meters* / *Show all*) and the mode is remembered in `wing_meters_solo`.

The card already had its own chevron, so collapsing the card itself was covered; this adds the "leave
only the meters" view.

## Fixed: the gradient could be missing on the first paint

Reported by the operator as "when a macro is activated the gradient seems to disappear". Reproduced: at
load the selected macro row had `background-image: none` (flat navy) and only picked up the ramp after
being selected again. The cause was ordering: the macro library arrives from the backend **after** the
dither module has run, so those rows are painted after the startup sweep and the mutation observer did
not always catch that first render. The module now does three cheap sweeps after boot (0, 300 and
1200 ms), which covers the first paint of the library and of any other surface created late.
