# WING CONTROLLER Desktop v0.2.57

Build: 20260927.2 (macOS Apple Silicon)
Date: 2026-09-27

The app now works for every console of the family rather than for the one on the bench, the long lists
read in two levels, the Shoot can be cancelled while it runs, and two things that could grow with time
are bounded. The crash-freeze reported while using the dropdowns is explained in the documentation: it
is a system-level wedge on this machine, not the window.

## For every WING, not for the one on the bench

The console announces its model when it answers discovery, and the app now reads it and uses it:

- **Meter groups are sized from the desk's own model.** The decoder assumed a local input group always
  carries 24 values; a full-size WING sends 8, so every group after it in the same datagram was decoded
  at the wrong offset. With no model announced the length is derived from the frame and the frame is
  truncated rather than shifted.
- **`/cfg/mon/<n>/$lvl` is a target where the surface has no control potentiometer** — a Rack or a
  Compact — and a watch on the full-size console (footnote 13 of the reference). The catalogue, the
  validator and the picker all follow the announced model instead of withholding the write everywhere.
- Category id bounds, the GPI/O count and the local input and output counts follow the same rule, and
  the status line names the model *family* only.

## The long lists read in two levels

"Source" carried sixteen input families in one flat run and "Destination" thirteen. The catalogue now
publishes a second level (Local, Stage box, Card & USB, Internal, Bus meters for the sources; Local,
Stage box, Card & USB for the outputs) and the drawn list heads each run of them under the group's own
heading, indented and inert to the pointer, with the keyboard walk never landing on a heading. The
meter card's own "Group / Source" list reads the same way. The `<optgroup>` keeps the coarse group
alone: the native list is what the rest of the app reads. The auxiliary *sources* row said "Aux Inputs"
where the backend says "Aux Sources", colliding with the Mix family's label.

## The Shoot can be cancelled, and a write the console did not confirm says so

While a Test Action runs, the button that fired it becomes **Cancel test action** and stops it —
including a wait or a fade being sent step by step. The run's own result is shown: `cancelled`, or
`completed_unconfirmed` when the console did not confirm a write, and the macro rows and the terminal
mark those steps `unconfirmed`.

## The FX parameters come from the model the slot runs

A step on an FX parameter offers exactly the parameters of the model selected on that slot, in one
"FX · <MODEL>" group, and a name the model does not have is labelled as missing instead of offered.
The model can now be **read from the console** (`/fx/<slot>/mdl`, bounded to the slots in use) instead
of being typed, with the manual field kept for a slot that does not answer.

## Two things that could grow with time

- The per-meter state (history, VU, peak hold) was keyed by meter and never pruned, so the window kept
  the history of every meter it had ever shown; it is now freed as soon as the console will no longer
  send it.
- A console that sends faster than the window can paint was the one unbounded queue. Both windows now
  paint the newest frame at most once per animation frame, merging the frames in between with the
  loudest value per meter, so a peak can never be lost and what is held is one frame rather than a
  backlog. The OSC terminal's own event stream is capped at 300 traces/s, and what the cap drops is
  announced in the terminal as a marked row rather than silently lost.

## The fallback catalogue is complete

The window's built-in catalogue (what it shows until the backend answers, and what it keeps if that
command fails) was missing fifteen of the backend's sixty category rows: the eleven output families and
mute groups, user controls, the monitor meters and the RTA bands. All fifteen are in, with their
parameters, and a new static test compares the two catalogues field by field so the gap cannot reopen.
The matrix button no longer offers the channel grid for a category it cannot address.

## About the freeze reported while reading the dropdowns

The window was not spinning: the system's own hang report shows the main thread waiting inside a
run-loop observer while a RunningBoardServices thread burns a whole CPU in a class lookup, with every
web process suspended — no JavaScript was running. The same wedge was then reproduced in headless
Chrome on this machine. Both are recorded, with the measurements that exclude the window, in
`docs/MACOS_HANG_RUNNINGBOARD_2026-09-27.md`.

## Verification

`cargo test --workspace` green (wing-core 160, desktop 167 + 3 ignored), the strict Maillot path audit
exit 0, every Node and browser contract green through `./scripts/verify-all.sh`, which now starts and
restarts the headless browser itself so a browser that dies mid-suite can no longer be reported as a
missing contract.
