# WING CONTROLLER Desktop v0.2.61

Build: 20260930.2 (macOS Apple Silicon)
Date: 2026-09-30

The toggle is the console's own flip now: one packet, no reading first, no waiting.

## What a toggle does

A toggle step sends one datagram carrying the integer `-1`. The console turns that into a flip of the
parameter it holds — the protocol documents it as *Special case: Toggle*: "by sending a -1 to an OSC
Command with an integer OSC Type Tag that can only accept values 0 or 1, the value of the parameter will
toggle between 0 and 1".

Nothing is read first, and that is the point:

- **No round trip.** The old version read the value, inverted it and wrote the result, which cost a read
  before every toggle — up to 400 ms when the desk did not answer, and in that case the step **failed**
  and nothing was sent. A toggle can no longer fail because a read did not come back.
- **No race.** Two presses arriving together used to read the same value and write the same inverse, so
  two presses flipped the parameter once. The console's flip is atomic: two packets are two flips.
- **No stale state.** There is no value to be wrong about, because the app never decides the result.
- **No queue.** The packet does not wait behind a fade's remaining packets, which is what the paced queue
  would otherwise make it do — up to a second late, and a mute that lands a second late is a wrong mute.

The one thing given up is the read-back confirmation: the console decided the result, so there is nothing
for the app to compare. The step is reported as **sent**, not as confirmed, and the Session Log line for
it says the console had nothing to compare. You see the desk's own answer in the OSC terminal, because
the app is subscribed to the console's state updates.

The old read-and-invert implementation is still in the code and still tested: if a console of the family
turns out not to implement the flip, that is where it is.

## Verification

`cargo test --workspace`: wing-core 161, desktop 180 (3 ignored), 0 failed, including three tests that
pin the new behaviour: the toggle sends exactly one packet carrying `-1` and reads nothing at all; two
toggles are two flips of the console's own state; and a toggle goes out even when the paced queue is
saturated past its bound, where a paced write is refused. There is also a hardware test for a real desk
(`LIVE_WING_TOGGLE_E2E=1 cargo test -p wing-controller-desktop live_wing_toggle_alternates_a_real_binary_parameter -- --nocapture`),
which flips a binary parameter twice and checks the console changed each time; it is the proof to run on
the desk this is used with.
