# WING CONTROLLER Desktop v0.2.76

Build: 20261004.6 (macOS Apple Silicon)
Date: 2026-10-04

A release about telling the operator the truth: the editor now describes what the runtime does, the file that holds your
work is harder to lose, and the security work the last two builds started is finished.

## What you will notice

- **The Rearm field stops describing a rule the detector never had.** It said a signal must fall below the threshold to
  re-arm. It does not: Rearm is a margin above the **lowest value seen since the trigger**, so a signal that stays loud
  can fire again after it forms a new low and rises by that margin. The hint and the guide say that now.
- **The timing fields offer the ranges the runtime actually uses.** Rearm offered −144 to 12 dB while the runtime keeps
  0.1 to 24, so it accepted a value that was thrown away and refused part of the range that works. Cooldown, dwell,
  stale, delay and fade are aligned the same way.
- **A macro written before those limits still opens and still saves.** It loads with its timing values brought inside
  the limits — the runtime's own behaviour — with a line in the log and a note in the header saying so. Nothing is
  rewritten behind your back until you save.

## Behind the scenes

- **Your library and your settings are harder to lose.** They are read with a size limit instead of being swallowed
  whole, and a recovery copy is now put back the way every other save is written: to a temporary, flushed, renamed and
  the folder flushed after it. A power cut in the middle can no longer leave you with half a file.
- **The unlock helper checks the application, not just its name.** It used to trust an application's identifier and
  version, both of which a tampered copy can simply claim. It now verifies the signature of the copy it is about to
  open and compares its hash with the one this download carries, and it refuses — naming the path and touching nothing
  — when they differ.
- **The window has a content policy.** It did not have one at all. Nothing loads from the network by policy now, and a
  regression test fails the build if it is removed again.
- **The OSC peer list is called what it is.** It is a filter of addresses, not authentication: a UDP packet carries
  whatever origin its sender writes into it. The window and the guide say so, and recommend connecting on this machine
  only.
- **The guide was corrected in two places** where it promised the opposite of what the code does, and the application
  no longer asks macOS for a microphone permission it never used.

## Still not proved

Two things this build cannot prove from the machine that made it, and both are worth knowing: timecode from a real LTC
signal (there is no interface here, only a built-in microphone, so nothing carries timecode), and the acceptance pass
with Mixing Station, which needs the desk. The inter-application feature is off by default and opens nothing until you
switch it on.
