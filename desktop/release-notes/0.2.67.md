# WING CONTROLLER Desktop v0.2.67

Build: 20261002.4 (macOS Apple Silicon)
Date: 2026-10-02

The second half of the audit work: the findings that changed behaviour, the test suite's own lies, and the two
decisions the plan was waiting for.

## The app

**A quiet meter stream no longer risks the session.** If the meter TCP connection goes, it is re-established
rather than left dead behind a Live badge; and the seven places that discarded a watchlist update when the
lock was poisoned now recover it instead of losing the operator's change without a trace.

**Fire Macro is refused while Live Safe Mode is on**, as the documents always promised. The window blocks it
like the twelve other actions it already covered. The backend's own padlock is never armed in a shipped
build, and that is now a decision with its reason written beside the code: arming it would refuse a Shoot, a
Fire Macro and a raw message — and a raw message is how a manual toggle reaches the console, so it would
refuse the performance itself.

**The lock has a test at last**, and it checks both directions: with the lock on, the click never reaches the
backend (an IPC counter stays at zero) and the refusal is visible and logged with its action; with the lock
off, the same click does reach it. The lock is a safety feature that nothing had ever asserted.

**Smaller**: the legacy fallback for an omitted action address no longer defaults to a real mute on channel 1;
the stress diagnostic's frame count is bounded; the Meter Bridge's Matrix button hovers in Stealth Dark (it
was specificity, not colour).

## The verification suite

**It can no longer book a run that did not happen as PASS.** Every browser suite ends with a seal the gate
demands, a machine without a browser fails instead of silently skipping the whole UI layer, and a passing
step's own "skipped" lines are printed beside its PASS. The Maillot audit refuses to judge an empty
inspection and now checks its 88 tolerated prefix mismatches against a reviewed, checked-in list — a new one
fails. `verify-install.sh` can no longer print "ALL CHECKS PASSED" having checked nothing, and
`./scripts/release.sh <version>` runs the build, the checksums and the verification in one step so they cannot
come apart.

## Decisions, written down rather than left open

The out-of-range **condition** value is still clamped (`meter < -999` becomes `< -120`) while an out-of-range
action value is refused. Refusing was rejected on purpose: this normalization runs on the compile path, which
is reached when a saved show is armed, so a refusal would stop a macro that runs today — the worst moment to
discover a value typed months ago. What is still owed is a preflight note naming the value that was written
and the value it became.

Phase 3 of the plan — one CDP driver instead of twenty-two, sleeps replaced by conditions, and the
forty-three functions duplicated between the two windows — is test infrastructure that changes nothing an
operator sees, and it lands after the show in batches with the gate green between them. The hardware pass and
the visual pass with the console connected are likewise owed, and only the desk can give them.
