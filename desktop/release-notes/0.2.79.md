# WING CONTROLLER Desktop v0.2.79

Build: 20261005.1 (macOS Apple Silicon)
Date: 2026-10-05

The cue panel, which is what the cue list was missing.

## What you will see

- **A chevron in the clock window.** Collapsed, nothing changes: the readout, the state, the next cue and Pin. Expand
  it and the window grows, remembers the size you left it at, and shows the cue list.
- **The list in timecode order, by default.** No more creating order: cues are laid out by their SMPTE time, wherever
  they were made or in how many passes. The selector offers **timecode**, **manual** or **the order they were added**.
  Whichever you choose is saved **in the show**, so opening the same cue file on another Mac keeps it.
- **Edit a time without deleting the cue.** A cue's time is four fields, hours down to frames, with buttons that nudge
  it by one or by ten frames. You can also add a cue at the position the clock is reading, and remove one.
- **Each row tells you where it stands**: its time, its macro, whether it is enabled, if it is the next one, and if it
  has already been resolved — in neutral words when the engine only knows it was resolved, because a cue it skipped is
  not a cue it fired.
- **Saving is a decision, not a side effect.** Editing changes nothing until you save, because **saving re-arms the cue
  list** — the button says so, and unsaved changes are marked. Holding a nudge arrow sends nothing at all.
- **The clock is smooth again.** The readout and the countdown were updating four times a second and moving in jumps;
  they now move continuously with the timecode.
- **The delivery line is visible while timecode runs**, with zeros when nothing has fired yet, instead of hiding until
  the first cue — a counter that answers "did anything go missing?" has to be able to say "nothing".

## Known limits

- **The window growth has only been exercised against a simulated frame.** If expanding does not resize the window on
  your Mac, that is the first thing to tell me: it is the one part the test harness cannot reach.
- The cue row is implemented in both windows rather than shared, because the packaged interface is four files with no
  bundler. Both are pinned by their own contracts so they cannot drift apart silently.
- A cue has no separate name yet: the row shows the note that was saved when the cue was made, and it is not editable.
- Adding a cue refuses if no timecode has arrived yet, rather than inventing midnight.
