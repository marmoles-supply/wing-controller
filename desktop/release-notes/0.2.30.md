# WING CONTROLLER Desktop v0.2.30

Build: 20260922.3 (macOS Apple Silicon)
Date: 2026-09-22

Three everyday fixes, reported by the operator.

## 1. The reason a macro cannot be enabled is now visible

Reported as *"it will not let me enable the macros, it stays off"*. The Enable button **refuses on
purpose** the macros that cannot run:

- `trigger not configured` — no category, channels or trigger parameter;
- `no runnable action step` — some step **with no target**.

The refusal was correct, but the reason was written **only to `streamOutput`**, which lives in the
Diagnostics card and is collapsed: the operator saw the toggle stay at `off` with no explanation at all.

Now `reportMacroCannotBeEnabled()` opens its own dialog with the reason and with what to do:

> **Cannot enable this macro**
> An enabled macro has to be able to run. Fix this first:
> • *NAME*: no runnable action step
> Set the action target in the step (or add a delay or HUD-alert step, which needs no target) and
> enable it again.

It applies to both paths (the toolbar button and the one in each row).

**Why it is so strict:** before, an empty step filled itself in with `/ch/1/mute`, so a blank
macro **fired a real mute on channel 1** with nobody having asked for it. Making it stricter was
correct; doing it in silence was not.

## 2. The W in About presses down like the other buttons

Pressing it only inverted the bevel; the rest of the buttons also **shift by 1 px**
(`transform: translate(1px, 1px)`), and that was the difference perceived as it not responding.
Verified by forcing the `:active` state: `transform: none` → `matrix(1, 0, 0, 1, 1, 1)`.

## 3. "Compact" really does change things (before it barely did anything)

Measured in the CSS: the base font was already 11 px and `density-compact` set 11 px again, `.panel`
went from `padding: 8px` to `8px 10px` (wider, not denser) and **a second compact rule further
down** fixed the base values again. Now, with a single rule and also **inside Settings**,
which is where the setting is changed:

| | Comfortable | Compact |
| --- | --- | --- |
| Base font | 11 px | 10 px |
| Panels | `8px` | `4px 6px` |
| Buttons and fields | 24 px | 20 px |
| Column gap | 6 px | 3 px |
| Settings navigation | `4px 6px` | `2px 5px` |
| Settings pages and rows | 12 px | 6 px |

## The Dock icon on macOS 26

macOS 26 forces icons into the *squircle* shape and composes a background behind the artwork; the only
thing it does not re-shape is a **custom icon**:

```
./scripts/set-custom-icon.sh "/Applications/WING CONTROLLER.app"     # after unlocking
./scripts/set-custom-icon.sh --check "/Applications/WING CONTROLLER.app"
```

## Corrections from the 2026-09-22 audit

- **The table describes the intent, not what the build did.** A later compact rule
  (`body.density-compact input/select { min-height: 26px; height: 26px }` and `button { min-height:
  26px }`) pushed the controls back up to **26 px**, two more than the 24 px of the standard mode: turning
  on "Compact" made the fields TALLER. The 2026-09-22 audit restored the 20 px of the table.
- **"With a single rule" was not accurate either**: there were still two compact blocks per selector and
  the second one won (the 26 px one). Now both say the same thing.
- The Settings padding goes from `10px 14px 24px` to `5px 7px`, not from 12 to 6.
- The verification header says **30 checks / 26 Node tests / 10 Chrome**; today they are 32 / 28 / 12, and
  the count lives in `scripts/verify-all.sh`.
