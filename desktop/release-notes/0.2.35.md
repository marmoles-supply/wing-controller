# WING CONTROLLER Desktop v0.2.35

Build: 20260922.8 (macOS Apple Silicon)
Date: 2026-09-22

Two fixes on top of 0.2.34: the Meter Bridge zoom no longer moves the side column's, and the interface
stops naming the aesthetics of the era.

## The Meter Bridge zoom no longer moves the side column's

Both windows wrote the same zoom key (`wing_meter_scale`) and in the real app they share storage (same
origin), so **moving the zoom in the popup also changed the side column meters'** — which is exactly the
opposite of what you want if one is on a stage screen and the other is compact on the desktop.

The bridge now has **its own key** (`wing_bridge_meter_scale`). If it does not exist yet, it inherits the
value from the working window **once only**, so nobody's size changes on update. Its change listener and
its reset button now use its own key.

## The interface does not name the aesthetics

No written references:

- The looks are called **"Light (Classic Slate)"** and **"Dark (FOH Low Glare)"**.
- The meter style is **"Task History Graph"**.
- Descriptions, tooltips, the context menu label and the title of the properties window, rewritten in
  neutral terms (*classic tooltip*, *the app's own context menu*, *history graph*…).
- The code comments of both windows, with the same meaning and without naming the era.
- Two internal identifiers renamed: `renderHistoryGraphs` and `initContextMenu`.

A new contract in the Settings test fails if "Win95" or "Windows 95" appear again in
`desktop/ui/index.html` or `desktop/ui/meters.html`.

## What already came from 0.2.34

The graph samples at the refresh rate (5..120 per second, measured: 120/s → 106 samples in one second) and
scroll decides how many seconds of history fit on screen; and the custom icon is no longer a manual step
(the build applies it and checks it, the unlock restores it and the helper travels inside the package).
