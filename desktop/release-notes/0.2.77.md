# WING CONTROLLER Desktop v0.2.77

Build: 20261004.7 (macOS Apple Silicon)
Date: 2026-10-04

A small release about being told what happened.

## What you will notice

- **Asking macOS for audio access now says what macOS did.** The answer — whether the system was asked, whether the
  device opened, how many inputs are visible afterwards — was being written and then immediately replaced by the
  device count, so pressing the button looked like nothing happening. Both are shown now.
- **A refusal names its reason.** Adding an application that the backend refuses said only "The application could not
  be added." even when the backend had explained exactly why. It keeps the reason now, and says the generic line only
  when there is nothing better to say.

- **The window no longer steals the focus from something you just opened.** Clicking a field queues a frame that
  gives the focus back to it; if that frame landed after a control had opened over it, the control lost the focus and
  closed itself — renaming a macro in place did exactly that, about two times in a hundred under load. The frame now
  takes the focus back only if nothing else has claimed it.

## Behind the scenes

- **The interface's own test harness can now fail on purpose.** It could only ever simulate a successful backend, which
  is why a message that erased itself went unnoticed: it checked that a click reached the code behind it, never the
  sentence an operator reads. It can now make any command refuse or answer anything, and six contracts assert the
  visible sentence — including a permission that is denied and one that is granted. Each was checked by reintroducing
  the defect and confirming the test goes red.

## Still not proved

Timecode from a real LTC signal: this machine has only its built-in microphone, which hears the room and carries no
timecode, so that still needs an interface or a virtual audio device at the desk. And the acceptance pass with Mixing
Station, which needs the desk itself.
