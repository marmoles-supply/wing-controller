# WING CONTROLLER Desktop v0.2.31

Build: 20260922.4 (macOS Apple Silicon)
Date: 2026-09-22

This release brings the **finishing touch of the era**: dithered gradients (ordered dithering) on the
surfaces, a ramped desktop background, decoration in About and three framing details you asked for.

## Ordered dither patterns on the surfaces

On 256-colour displays the gradients of Windows 98 and Encarta **were not smooth gradients**: they were
**dithered** ramps, with the colour mixed pixel by pixel through an ordered matrix. What is painted flat
today is a modern simplification, so restoring the dither is more faithful, not less.

- **Title bars of dialogs and popups**: blue ramp `#000080 → #1084d0` with a 4×4 Bayer matrix and
  cells of 3 px, with the base colour held for the first 30 %. That detail is what makes it read
  as a **sheen** and not as a background gradient.
- **Panels and card headers**: the same idea in grey. In the dark theme, their greenish
  equivalents.
- **Settings → About**: dithered radial halo behind the app logo and a dithered **brand band** under the
  heading, which is where there is more freedom without disturbing the reading.

Two technical decisions that matter and that show on screen:

1. **The pattern is generated at the exact size of the element**, it is not stretched. Stretching a small
   pattern (what I did in the first tests) produced **rectangular** cells and **vertical lines**. Now the
   cell comes out square: measured in the panel, **3.99 × 4.01 px**.
2. **It is drawn once and cached as a PNG** per combination of colour, size and cell. An inline vector
   pattern cost megabytes of CSS; the PNG of a normal element is a few KB.

## Desktop background and framing

- **The desktop carries a dithered ramp**: dark teal at the top, lighter at the bottom, with cells of
  4 px. It is generated for the size of the **window** and stays fixed, so it is not regenerated when the
  content grows and it does not shift while scrolling.
- **The seam between the main block and the side column is no longer a grey band**: it is transparent and
  lets the desktop background show through. The 2 px resize handle stays visible.
- **1 px of margin on the right** in the blue bars, with `background-clip: padding-box`, so the blue does
  not touch the black bevel.

## The Dock icon on macOS 26

macOS 26 forces icons into the *squircle* shape and composes a background behind the artwork. The only
thing it does not re-shape is a **custom icon**:

```
./scripts/set-custom-icon.sh "/Applications/WING CONTROLLER.app"     # after unlocking
./scripts/set-custom-icon.sh --check "/Applications/WING CONTROLLER.app"
```

## Verification

`./scripts/verify-all.sh`: **31 checks** — TypeScript, syntax of both windows, 27 Node tests (11 of them
driving the real UI in Chrome) and `cargo test --workspace`.

The new test `scripts/test-desktop-dither-browser.mjs` pins down what took a while to get right: that the
pattern is a purpose-built PNG (not stretched), that the cell is square, that a hidden dialog is painted
when it opens, that About is painted when its tab is opened and that the blue bars carry their 1 px
margin.

The gate has also been hardened: before the browser tests it closes the tabs pointing at the dead
temporary server on `:8080`. A zombie tab from a previous run brought down five tests and looked like a
code failure.

## Corrections from the 2026-09-22 audit

- **The desktop ramp was not diagonal in this build.** The 0.2.31 commit varied the ramp only in x
  (`dither.js`: `const base = cols > 1 ? x / (cols - 1) : 0`); the diagonal arrives in commit `32ca3a93`,
  later than the DMG of this release (10:03) and already part of 0.2.32. For the same reason, the
  "pre-painting", the diagonal and the row highlight that 0.2.32 and 0.2.33 list as inherited from
  0.2.31 belong to 0.2.32 (`CHANGELOG.md` attributes them there).
- The verification header says **30 checks**; today there are 32.
