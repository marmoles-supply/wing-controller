# WING CONTROLLER Desktop v0.2.62

Build: 20261001.1 (macOS Apple Silicon)
Date: 2026-10-01

The show-readiness audit: one instance only, no data is not silence, the emergency stop tested as one
action, and the release verification as a script.

This build carries everything the stability audit changed before the shows. No new protocol features:
every item is a fix, a bound or a test.

## A second launch can no longer start a second application

Forcing a second launch (`open -n`, a double launch while the first is still starting, or the copy on a
mounted disk image beside the installed one) used to start a second application: two streams on one
desk, two windows writing the same library and show files (last one wins) and two runtimes able to fire
the same macro. For a **toggle** that is two flips and a parameter that ends exactly where it started.
The second launch now focuses the window that is already open and exits.

## A meter with no value is no longer painted as silence

A meter the frame did not carry was painted at the bottom of the scale: `-inf dB`, the bar at rest, and
the peak hold remembered a peak for it. "The console reports silence" and "this window has no value for
this meter" were the same display. Now:

- **no value** → `–`, an empty bar and `PK --`, and nothing is remembered for it;
- **a value the console reported** at the bottom of the scale → `-inf`, as before;
- both windows (the workstation and the Meter Bridge), including its templates before the first frame.

## The emergency stop is tested as one action

PANIC STOP stops the stream **and** cancels a Shoot in flight. Each half had tests; the command that has
to do both did not, and an emergency stop that leaves a fade running is not an emergency stop. It now
has one, and it also proves the run slot is empty afterwards.

## The release verification is a script

`scripts/verify-install.sh <version>` runs the checks that used to live in the project's head and prints
PASS/FAIL for each: the artefacts and their hashes, the application inside the DMG (version, signature
and its install instructions), that no volume is left mounted, and with `--install` the installed copy
and its single instance.

## Documents

- **`docs/SHOW_MACHINE_RUNBOOK.md`** — the show machine, in order: install (and never run from the disk
  image), one instance one desk, verify the link, save the show as the rollback, Live Safe Mode before
  doors, what a Shoot's `elapsed=` means, what PANIC STOP does to a fade, and what to capture if
  something goes wrong.
- **`docs/SHOW_READINESS_PLAN_2026-09-30.md`** and **`docs/SHOW_READINESS_RESULTS_2026-09-30.md`** — the
  audit, phase by phase, with its measured numbers, its findings and the one it deliberately did not
  finish (a test that only passes in a fresh browser, with its reproducer).
- The DMG and ZIP instructions now say it outright: install the application into `/Applications` and do
  not run it from the disk image, because macOS can wedge an app running from a mounted volume.

## Measured, so the numbers are on the record

- toggle **0.2 ms** (one packet, no read, no queue), set 34.7 ms, 300 ms fade 403 ms, a read-back the
  console never answers 183.8 ms;
- 20-minute soak of both windows: 48 meters at 60 frames/s and 300 OSC traces/s sustained — heap, DOM
  and frame interval flat, the browser ending lighter than it started;
- the runtime under sixteen simultaneous macros: dispatch from frame to run **p50 1.1 ms, p95 2.9 ms**,
  with every refusal counted rather than silent.
