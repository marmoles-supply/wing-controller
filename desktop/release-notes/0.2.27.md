# WING CONTROLLER Desktop v0.2.27

Build: 20260921.14 (macOS Apple Silicon)
Date: 2026-09-21

## Typing never lies to you again: the editor now validates what you type

Reported from the desk: `asdoijasod` in Threshold and `iuanf4ur` in the channel list were saved
without a word, and the macro then did nothing on the console. Every field now has a rule:

- **Numbers** (Threshold, Rearm, Delay, Fade, cooldowns) must be numbers, inside their range and
  their unit, with whole numbers where the console wants integers.
- **Channel lists** must use the grammar `1,3-5`, must start at 1 and must fit the selected
  family (`999` is refused on a 40-channel family, and the message says how many there are).
- **The OSC address** must look like an address (`/ch/1/mute`).
- **On/off and choice parameters** accept only their values, and are checked against the plugin
  model the parameter belongs to.
- **The macro name** cannot be blank or absurdly long.

An invalid value is marked **where it is** — red inset, the reason underneath and in the tooltip —
as it is typed, and **saving the draft or arming the macro is refused** with a dialog that lists
what is wrong and focuses the first offending field. An empty field is a work in progress, not an
error: a half-built macro still saves, and the app keeps refusing to arm it with its own reason.

## Custom banks in the Meter Bridge

The bridge sidebar now has a **Custom banks** section, under a rule and clearly apart from the
standard groups:

- **+ New from watchlist** saves the meters you have in the watchlist as a named bank
  (the name is asked in the app's own Win95 prompt, because `window.prompt()` returns nothing in
  the packaged app).
- Clicking a bank shows only its meters; the tab shows the name and how many meters it holds.
- **Right-click a bank** to rename it, refresh it from the current watchlist, or delete it (with
  confirmation).
- Banks are stored in `wing_meter_banks`, which the Meter Bridge owns in this build. The
  workstation window reads and writes the same key from the next build on, so a bank created in
  either window will then be the same data.

## Quitting always asks

- Closing the window asks **whether or not** there are unsaved changes: this is a live-desk tool and
  the window is one click away from the meters.
- **Cmd+Q** used to quit silently: Tauri's predefined Quit goes straight to `terminate:` and never
  raises `RunEvent::ExitRequested`, so it could not be intercepted. The app now builds its own menu
  (mirroring the default one, so Cut/Copy/Paste are intact) with a Quit item that asks through the
  same dialog.

## The seam between the two columns was 24px wide

The layout added the resizer's 8px **plus** the two 8px grid gaps. The column gap is now 0, the
resizer measures 6px, and it wears the panel colour instead of letting the page background show
through as a coloured stripe — with the 2px groove that lights up amber on hover.

## Still from 0.2.26 and 0.2.25 (this is the build to test them in)

- **Clicking a field and typing works**: WebKit keeps the DOM focus but closes its editing pipeline,
  so the caret has to be re-established after the click (`placeCaret`). Holding the mouse button
  used to be the only way, and right-click → Edit worked because it calls `select()`.
- **Closing the app closes it**: `core:window:allow-destroy` was not granted, so Tauri's own
  `destroy()` was rejected and the window never closed.
- The confirmation dialogs are 400px wide instead of the size of the Preferences window, a click on
  a value selects it so typing overwrites it, and settings block titles cut their line cleanly.
