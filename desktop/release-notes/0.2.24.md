# WING CONTROLLER Desktop v0.2.24

Build: 20260921.11 (macOS Apple Silicon)
Date: 2026-09-21

## The click: reproduced, and this time the fix targets what was measured

The operator's report was the breakthrough: *"it only works while I hold the click; if I
release it I cannot type"*. That is a precise signature, and it reproduced in the WKWebView
harness (`scripts/dev-webkit-probe.swift --hold`):

```
button held     +'1': {"ok":true,"value":"1"}     editing allowed while the button is down
button released +'2': {"ok":false,"value":"1"}    WebKit refuses the edit the moment it is released
active on release: INPUT#macro-name               the DOM focus is still the field
```

So the DOM focus was never the problem: **WebKit grants the page focus on the mouse-down and
takes it back on the mouse-up**, which is why keeping the button pressed let the operator type
and releasing it made the field deaf. `window.focus()` does not restore it (measured: it stays
`false`), so the claim has to come from the window/webview side.

What this release changes:

- A single `claimFieldFocus(field)` path asks for the window (`setFocus`, needs
  `core:window:allow-set-focus`) **and** the webview (`focus_webview` → `Webview::set_focus()`).
- It runs on `pointerdown`, **and again on `pointerup`** once the platform has finished handling
  the release — the claim that was missing.
- After a click, the focus is re-checked a few times over the next second (bounded, and only
  while the operator is still in the same field), so a revocation that lands late is undone.
- Failures are logged as `window_focus_failed` / `webview_focus_failed` instead of vanishing.

Applied to both windows. If it still does not work, the useful datum is whether the session log
shows either of those two lines.

## Also in this build (since 0.2.22)

- **`window.confirm()` returns false in the app**: Clear, Panic Stop, the backup restore, the
  factory reset, "Replace & View" and the unsaved-draft guard were cancelling themselves in
  silence. Both windows now own a Win95 confirmation dialog, and a contract test fails if a
  native `confirm` call comes back.
- **Strip models are read and shown**: `read_strip_models` reads `/gate/mdl`, `/dyn/mdl` and
  `/eq/mdl` for the selected channels and the Action panel shows the result under the parameter
  selector; the parameter dropdown then offers that model's own appendix parameters
  (`gate:1-thr`), validated against the generated table before building the address.
- **Settings block titles** cut their line cleanly again.
