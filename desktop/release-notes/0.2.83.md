# WING CONTROLLER Desktop v0.2.83

Build: 20261005.5 (macOS Apple Silicon)
Date: 2026-10-05

## The panels could not exist, and now they are asked for where macOS builds windows

Every native panel in this application - choosing an LTC file to verify, importing and exporting a macro library, the
station backup's save and folder panels - was asked for from a **worker thread**. On macOS a window can only be created on
the **main thread**: asked from anywhere else, the panel never appears, raises no error, and its callback never fires, so
the command waited out its whole timeout and answered nothing. That is why an operator saw "nothing happens", and why
**all** of them failed together while the rest of the window kept working - they were the same mistake in five places.

All five now ask with `run_on_main_thread`, keeping the channel and the timeout as the safety net rather than the
mechanism. Two more of the same shape, from the same week, are included:

- **The LTC file panel opened on every rate the selector offers.** Choosing 29.97 did nothing at all, because the reader
  kept a second, narrower list of rates and refused it before the panel could be asked for.
- **No audio button can stay silent.** Refresh and Ask macOS for microphone access touched CoreAudio through a promise
  that could neither resolve nor reject, so neither the code after it nor its error path ran.
