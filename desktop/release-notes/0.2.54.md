# WING CONTROLLER Desktop v0.2.54

Build: 20260926.1 (macOS Apple Silicon)
Date: 2026-09-26

The whole macro target list of the last six batches is in this build — show control, solo, talkback,
GPIO, routing, the oscillator, the transport, the fader layers, the strip long tail and the desk
level — and the parts of it that could only be guessed before were settled against a real desk. Two
window annoyances are gone with them: one grouped picker per field instead of two dropdowns, and no
hover ScreenTip over an open dropdown.

## The desk level is a macro target

Nine categories and 130 keys, every one quoted from the reference and pinned by a test:

- **Monitor buses** 1…2: polarity, pan, width, the eight-band EQ, the limiter, the delay, dim and PFL
  dim, band solo trim, source level and mix, the source list, the direct input and tags.
- **Solo configuration**: the mode (LIVE, STUDIO, SIP), the monitor destination, the mute, the four
  taps and the three switches the desk's surface drives (`Solo Dim`, `Solo Mono`, `Solo Flip`), with
  the three source-solo reports as watches.
- **Console lights** (the eleven documented rows) and the **safe masks** — one character per item,
  `+` for safe — so a macro can light the desk up while it is armed and protect a section before a
  scene load.
- **W-Live multitrack**: ten commands (transport, sessions, markers, the time to jump to, naming, set
  marker, format the card) with the transport state and the card identity as watches.
- **AES50 health**: link state, device and both error counters as watches, the documented error reset
  as a command.
- **Clock lock and PPM** as watches, and the **global clock rate, clock source, startup mute, USB and
  StageConnect configuration** as writes.

## Two rules the batch needed

A key the console only **reports** can never be a step. The editor never offered one, but the read-only
leaf resolved like any other, so a hand-edited show file could arm a write the console ignores while
the macro reported success. The editor, the save validator, the Shoot button and the compile path all
refuse it now, with the reason.

A write-only **command** is sent and not read back: what such a command changes is reported at another
leaf, so `W-Live Control = REC` used to report "the console did not apply …" for a write that landed.
Toggle and Fade are refused there too — both have to read the leaf first — and Verify Targets labels
the address.

## What the desk settled

The console (a WING Rack, verified on hardware) answered the checks the last build left open:

- **`/ch/N/ptap` is offered now.** It is a string enum: all eight documented values (`IN, FILT, 3, 4,
  5, PFL, AFL, POST`) are taken verbatim, an int write is ignored, and a value outside the list leaves
  the previous one in place. The reference's own dumps print `ptap=4` because that is how a dump
  renders the string.
- **`comp_ratio` was never broken**: a float write lands on a channel, which is what the app sends.
- **The `gate_*`/`dyn_*` leaves are readable and pushed**: a `/*S` subscription delivers the change
  (writing `/ch/1/mute` produced one unsolicited `/ch/1/$mute`).
- **`/$ctl/safes/output/A`** is the console's spelling; the extraction's `outpu/A` answers nothing.
- **The six unmarked solo `$` rows split**: `$dim`, `$mono` and `$flip` latch a write and became
  targets; `$srcsolo`, `$srcsgrp` and `$srcsin` do not and stay watches.
- The **batch's own writes** land: lights, safe masks, monitor pan and EQ switch, solo mute.

## One control per choice, and a quiet dropdown

The window drew the flat native list *and* a grouped button under it: two dropdowns of different
shapes for the same choice. A native list cannot carry the two levels the picker needs, so the grouped
button is now the field's only control — it wears the field's own white box, carries the field's
ScreenTip, and the native list stays in the DOM hidden as the value holder every other part of the
editor reads. The field's label points at the button, so clicking the word "Parameter" opens the
picker, and validation keeps working on the hidden source.

The hover ScreenTip and the Inspector readout no longer follow the cursor across an open dropdown:
they covered the very rows being read. Inside the open list neither is driven; everywhere else the
hint behaves as before.
