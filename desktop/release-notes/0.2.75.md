# WING CONTROLLER Desktop v0.2.75

Build: 20261004.5 (macOS Apple Silicon)
Date: 2026-10-04

The audio device list, and the trap behind it.

## What the owner saw

Pressing **Refresh** on the Timecode page produced no devices. The listing works — it is proved against this machine's
own microphone from a test binary — so the difference is the **application's** context, and the likeliest cause is the
trap macOS sets around audio input:

- the system asks for the microphone **only when a stream starts**;
- until that permission is granted, an application can be told there are **no input devices at all**.

Which is a circle: the operator cannot choose a device that is not listed, so nothing ever starts a stream, so nothing
ever asks. The list stays empty for ever and the feature looks broken.

## What is different now

- **The default input device is always offered**, even when the enumeration comes back empty. The operator always has
  something to select, and selecting it and pressing **Listen** is what makes the system ask.
- **A button to ask directly**: *Ask macOS for access* opens the default input for a moment, which is what triggers
  the prompt, and then re-lists and says how many devices are visible — the honest measure, because macOS gives
  silence rather than an error when it refuses.
- **The empty list explains itself** instead of saying "no audio inputs": it says that the system is probably hiding
  them, what to press, and that timecode needs an interface or a virtual device (BlackHole, Loopback) because the
  built-in microphone hears the room.

The fix holds even if the diagnosis is wrong: an empty list is no longer a dead end.

## Still not proved

A real LTC signal: this machine's only input is its own microphone, so nothing here carries timecode. And the
Mixing Station acceptance pass.
