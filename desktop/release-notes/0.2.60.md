# WING CONTROLLER Desktop v0.2.60

Build: 20260930.1 (macOS Apple Silicon)
Date: 2026-09-30

A mute is instant again, and the window stops freezing while the application looks for the desk. This
build follows 0.2.59 and fixes a latency regression that came in with the model-aware work.

## What was wrong

Every operator action asked the console to introduce itself before doing its work. The Shoot (*Test
Action*), a raw send, and every strip or FX model read the editor makes all began with a discovery
exchange — `WING?` on UDP 2222 and the desk's answer — and that exchange waits **650 ms per network
adapter**, plus one more wait on the system default when none of them answers. On a machine with a
second adapter, against a desk busy streaming meters, that is what "a simple mute takes ages" was.

Measured on this machine, with a desk that does not answer discovery promptly: **1.302 s per click**.
Measured with the route remembered: **0.6 ms**.

## What it does now

- **The route to a desk is remembered**: which local address it answered on, and the model it announced.
  The live session fills that in when you connect, so the first Shoot of a session costs nothing extra,
  and the answer is reused for every action after it — per console and per adapter choice, never mixed
  between two desks or two adapters.
- **Each action still binds its own socket** to the remembered address, so two commands can never take
  each other's replies.
- **The memory is forgotten when it stops being true**: a raw send that fails, or a whole model read
  that comes back silent, drops it, and the next action discovers the desk again instead of writing
  through an adapter that has gone away. The remembered route also expires on its own.
- **Discover and Verify WING still sweep every adapter**, and they now do it without freezing the
  window: `send_osc_message` and the Discover sweep were the two commands declared without `(async)`,
  which makes Tauri run them on the main thread, so the whole window waited for the sweep. Both run on
  the threadpool now, like the commands that already did.
- **The Shoot says how long it took.** The Session Log line of a test send now ends with
  `elapsed=<n>ms`, measured from your click to the run's answer, so a slow action can be reported as a
  number instead of an impression.

## Verification

`cargo test --workspace`: wing-core 161, desktop 177 (3 ignored), 0 failed. `./scripts/verify-all.sh`:
every step green. The two new tests pin the contract that broke: a remembered route is reused without
asking the desk again (there is no discovery responder in the test, so a probe could not succeed), and a
remembered route belongs to one desk and one adapter choice — another address, another adapter, strict
mode or a stale answer is a different route.
