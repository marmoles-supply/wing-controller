# WING CONTROLLER Desktop v0.2.85

Build: 20261005.7 (macOS Apple Silicon)
Date: 2026-10-05

## A macro with no trigger of its own, and a Save button you cannot miss

**A macro can now be built to be fired only by a timecode cue.** The Source select's empty entry said "— Not configured —",
and the macro editor refused to enable a macro whose trigger was empty - so an operator who wanted a cue to be the only
thing that fires a macro had to give it a trigger he did not want, and then worry, rightly, that it might fire on its own.
The entry is now a named choice, "Only a cue fires it (no trigger of its own)", and only a **partly** filled trigger is
still refused as incomplete. Nothing was added to the engine: it already skipped an enabled macro with an empty trigger
from its own scheduling, and a cue already fires a macro by its position in the library without consulting the trigger. The
row, the WHEN summary, the recipe and the row inspector now all say what the label says, instead of "NOT CONFIGURED".

**The Save button in the cue panel is now the action.** It was neutral grey and the owner spent a session not seeing it,
which is how a cue ended up looking broken. It is a solid action green when everything is saved, and amber with a slow
pulse and a marker while there are unsaved changes. The unsaved state is read from the same predicate that already paints
the window's own "Unsaved changes" line, so the button and the notice cannot disagree. Under a system request for reduced
motion there is no animation at all, and the state is carried by colour, outline and marker instead: an animation is never
the only signal.


## An action target over several channels now writes to all of them

A target spanning a range - the operator typed 9-12 - muted only channel 9. The core expanded the range correctly and the
window showed "4 targets", but everything downstream kept a single address string: the compiled step held one `address`,
and the send path wrote one packet. The step now carries the selector, resolves it at compile time into the list of
addresses, and writes one OSC message per channel - in the plain send, in the ramp, in the toggle and in the read-back,
with the packet count and the run report saying what was actually sent.

The suite could not have caught it: its test harness's stand-in for the resolver split on commas and never expanded a
range, and no test in the repository ever typed one. That stub is now faithful to the resolver, including reverse ranges,
duplicates and the cap, and a new check drives the window with `9-12` and requires the whole range to survive.
