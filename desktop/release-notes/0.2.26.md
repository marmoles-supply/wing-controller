# WING CONTROLLER Desktop v0.2.26

Build: 20260921.13 (macOS Apple Silicon)
Date: 2026-09-21

## Closing the app now closes it

Clicking the red button often did nothing and the app could only be force-quit. Two causes,
both fixed:

- **`core:window:allow-destroy` was not granted.** `onCloseRequested` is closed by Tauri's own
  JS wrapper, which calls `destroy()` on the window afterwards; without the permission that
  call is rejected, so the window simply never closed. The capability now grants it, and a
  contract test fails if a window listens for `onCloseRequested` without being allowed to
  destroy itself.
- **macOS keeps an app alive after its last window closes**, so even a successful destroy left
  the process and its Dock icon behind. The main window's destroy event now exits the process
  explicitly (after closing the Meter Bridge and stopping the stream).
- The confirmation dialog had its buttons **inverted**: "Close" called `preventDefault()` and
  kept the app open. Accepting now closes and only "Keep editing" prevents the close, and the
  button reads "Close without saving".

Verified on a real instance of the built app: with a clean draft the red button exits
immediately; with unsaved changes the dialog appears and "Close without saving" exits.

## The confirmation dialogs are small again

The reusable dialog inherited the base `.win95-dialog` size (650x560, the size of the
Preferences window) and with two lines of text looked absurd. It is now 400px wide and fits
its content (~108px tall) in both windows.

## Clicking a value selects it

A click on a field selects its whole content so typing overwrites it (a second click inside
the field places the caret where you point). The value no longer ends up with the caret at
the left edge, and the selection is also what re-opens WebKit's editing pipeline, so typing
keeps working.

## About the app icon

The Dock was showing a dark rounded square for the installed copy. The `icon.icns` in every
mounted build (1.2.20, 1.2.21, 0.2.22, 0.2.23) and in the source has **pure alpha around the
marble W** — it is the transparent W the operator prefers. What was on screen was macOS's
cached icon for an older bundle path, so LaunchServices was refreshed for those volumes and
the Dock was restarted. The build now also refuses to package an icon that has lost its alpha
channel, so this cannot regress.
