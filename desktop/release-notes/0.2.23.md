# WING CONTROLLER Desktop v0.2.23

Build: 20260921.10 (macOS Apple Silicon)
Date: 2026-09-21

## The click that starts editing (third attempt, new mechanism)

Two fixes were tried before this one and neither worked, so this release changes what it
attacks. Measured in the packaged app with the macOS accessibility tree:

- A click **does** focus the field: the focused `AXTextField` becomes the one clicked. That
  was already true, so the previous attempts were aiming at the wrong layer.
- Keyboard input **does** reach the app when the window is genuinely key (`F1` opened the
  built-in manual), and does not when it is not.
- `setFocus()` was rejected in 1.2.21 because the capability did not grant it; 0.2.22
  granted it and claimed the window on every click. It still did not work, so the window
  was not the missing piece either.

What remains is the layer between them: **WebKit only accepts text input while its own view
is the window's first responder**, and `WebviewWindow::set_focus()` raises the window
*without* giving the webview that status. This release adds a `focus_webview` command that
reaches `Webview::set_focus()` (the Tauri `unstable` feature exposes `Manager::get_webview`),
the app hands focus to the webview every time the window gains it, and a click over a
typeable field now asks for both the window and the webview. If either is refused, the
session log records `window_focus_failed` or `webview_focus_failed` instead of failing in
silence — that log line is what to look for if this still does not work.

## `window.confirm()` returns false in the app: several buttons did nothing

WKWebView has no dialog delegate, so `window.confirm()` returns `false` without asking, and
every confirmation written with it cancelled its own action:

- **Clear** in the meters panel (the reported one)
- **Panic Stop** (it asked for confirmation and then cancelled itself)
- Station-backup restore, factory reset, and **Replace & View** in both windows
- The unsaved-draft guard when switching macros

Both windows now own a Win95 confirmation dialog (`win95Confirm` / `metersConfirm`): Enter
accepts, Escape cancels, clicking the backdrop cancels, and the dialog owns the keyboard
while it is up. `test-desktop-ui-contracts.mjs` fails if a native `confirm` call comes back
(comment-aware), so this cannot regress quietly.

## Strip models are read and shown

The generated catalogue knows every plugin's parameters, but nothing asked the console which
model each strip runs — and the model decides which parameters exist. A new read-only command
`read_strip_models` reads `/gate/mdl`, `/dyn/mdl` and `/eq/mdl` for the selected channels and
the Action panel shows the result under the parameter selector, e.g.
`GATE 3=DEQ2 · DYN 3=WARM · EQ 3=STD`; a slot that stays silent is reported as `silent`,
which is exactly why a write to the generic name is ignored. The read is debounced (one round
trip per edit, not per keystroke) and a newer edit discards an older answer before it paints.

## Interface

- **Settings block titles cut their line cleanly again**: fieldset legends carry an explicit
  block of the panel's own colour behind the title (themed, so dark mode follows), so the
  border stops at the text instead of running into the glyphs.
- The meter watchlist still starts empty, Clear is the only list action, and the matrix and
  bridge selectors keep their vertical sidebars.

## What to check first

1. Click a text box once and type: the caret must appear and the characters must land.
2. If not, open the session log and search for `window_focus_failed` or
   `webview_focus_failed`: either line tells us which layer refused the focus.
3. Press **Clear** in the meters panel with meters loaded: the Win95 dialog must appear and
   accepting it must empty the list.
