# WING CONTROLLER Desktop v1.2.19

Build: 20260921.6 (macOS Apple Silicon)
Date: 2026-09-21

This release is a correctness and usability pass: the macro test button now runs
the real dispatcher, a stale action target can no longer be sent or saved, a new
macro starts empty instead of pretending to be configured, the library stops
losing work, and the whole interface was audited against the Win95 design it
claims to follow. No protocol behaviour was changed without hardware evidence.

## Test Action (Shoot) runs the macro's own dispatcher

The button used to send raw OSC with the step's address and value, bypassing the
macro executor. A **Toggle** step carries no value by design, so the test sent a
fixed value and the parameter never alternated, while the timeline toggled
correctly. The button now runs the selected step through the same dispatcher a
macro run uses, so toggle, fade, delay and HUD alerts behave identically, and the
read-back confirmation that reports an ignored write applies to the test too.

## A changed action target is never sent or saved as the old one

The OSC address is resolved asynchronously (debounced preview plus the target
change handler), so clicking Shoot, Save Draft or Arm could read the config before
the new channel had resolved and fire the **previous** channel's command. Every
path that reads the config now resolves the current target first; when a
configured target does not resolve, the address is cleared instead of keeping the
old one. Toggle is only offered for on/off parameters (and for a custom address,
which preflight judges).

## A new macro starts unconfigured

The New button used to hand out a macro that already read `usb 1 meter ->
/ch/1/mute`, and the normaliser painted those defaults back on every save, so a
blank macro looked ready to listen and fire. Trigger source, channel and parameter
now start empty, `Add step` adds an unconfigured step, and an empty value is
preserved as empty. An enabled macro that is not configured cannot be switched on
and preflight explains what is missing; an incomplete macro no longer breaks the
session (it is skipped and reported) and saving a changed macro re-applies it to a
running session (`live_macros_reapplied`).

## Work is not lost any more

- Switching macros, creating, duplicating, importing or deleting asks before
  discarding an unsaved draft, and the delete dialog says the editor changes will
  be lost.
- "Replace & View" and "Clear" confirm before wiping the meter watchlist.
- The legacy "demo alias" purge only runs when the whole watchlist is legacy demo
  data; it used to delete every configured meter if a single alias matched.
- "Connect + Listen" no longer saves a half-finished draft without saying so.
- Live Safe Mode is real: with the stream running it blocks saving the draft,
  creating, enabling, deleting, duplicating, importing, reordering and the factory
  reset, explains why, and disables the buttons involved. The editor still takes
  typing; nothing can be committed to the library until you disconnect.

## Interface audit (measured, not guessed)

Three read-only audits measured the real interface in Chrome. Fixed from their
findings:

- The header overflowed by 174 px at the window's own minimum width and pushed
  Properties, Help and Meters off-screen.
- The column divider followed the pointer 51 px behind (and backwards in the
  left-sidebar layout); a 480 px dead strip appeared when the columns stack.
- Live telemetry was amber on grey at 1.45:1 (invisible), the Meter Bridge peak
  number was 1.19:1, and the status badges and HUD used a web palette instead of
  the Win95 one. Meter Bridge text now grows with the zoom, VU and History show a
  numeric level, and the bridge releases its meter source when it closes.
- A dialog owns the keyboard: global shortcuts no longer change the macro behind
  a modal, the Matrix takes focus, and F12 still reaches the panic stop with a
  dialog open.
- Win95 details: hard shadows instead of blur, monochrome glyphs instead of
  colour emoji, hidden table-striped leftovers and a stray CSS declaration fixed.
- Help and About say what the app does (seven action modes, Card/Dante inputs up
  to 64, bridge shortcuts, the 1/256 dB scale, the `/meters/<family>/<id>` leaf)
  and the bridge About carries the legal notice and copyright.

## Model-dependent parameters are now selectable

Gate and compressor parameter names belong to the model loaded in the strip
(Maillot 3.1.0, plugin appendices): a strip running `DEQ2` has no `/gate/thr` and
a `WARM` compressor has no `/dyn/thr`. The catalogue now offers the model's real
parameters — `/gate/1-thr`, `/gate/2-thr`, `/gate/1-g` for DEQ2 and `/dyn/drv`,
`/dyn/trim`, `/dyn/mix` for WARM — with their documented ranges, and the path
audit indexes the plugin appendices so the strict check stays at zero unknown
addresses. Every new path was confirmed by reading the console (a WING Rack,
verified on hardware).

## Verification

`./scripts/verify-all.sh` (17 checks: TypeScript, both windows' script syntax,
every Node test, two of them driving the real UI in Chrome, the strict Maillot
path audit and `cargo test --workspace`). The browser tests run under a watchdog
so a hung one fails the gate instead of blocking the session. Rust: 81 desktop
tests plus the crate suites, including a fake-console toggle test and snapshot
pruning.
