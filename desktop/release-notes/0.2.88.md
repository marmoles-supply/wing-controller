# WING CONTROLLER Desktop v0.2.88

Build: 20261005.10 (macOS Apple Silicon)
Date: 2026-10-05

## The cue-only macro reaches the door it was knocking on

0.2.87 made the editor leave the trigger genuinely empty when the operator chooses "only a cue fires it", and it
was still refused - because the same rule lived in a fourth place, and that one was the check the window runs
before it arms anything: the backend's preflight. It read an empty source, channel or parameter as "not
configured", so a macro with no trigger of its own was refused there while the editor was content.

The rule now reads the same in all four places, and the preflight treats only a **partly** filled trigger as
unfinished. A macro with no trigger of its own passes the preflight, keeps being skipped by the runtime as
something with nothing to watch, and is fired by its cue through the library index. Half a trigger is still
refused, and still says which three things to choose.
