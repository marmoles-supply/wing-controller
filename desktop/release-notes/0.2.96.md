# WING CONTROLLER Desktop v0.2.96

Build: 20261009.1 (macOS Apple Silicon)
Date: 2026-10-09

## The fields behave the way you asked, in every window

You asked for two things from one gesture: *"cuando se clica una vez, se selecciona todo el texto… el segundo
clic tiene que hacer que el cursor vaya a la derecha del todo"* — and for it to hold in every cell of every
screen and pop-up. It does now, and the reason it did not is worth saying.

**The rule lived in two windows and nowhere else.** The main window and the meter bridge each carried their own
copy; the LTC, Timecode and guide windows carried none at all, so the same gesture behaved three different ways
and three windows had the fields that were hardest to type in. It is one module now
(`desktop/ui/field-editing.js`), loaded by all five.

**The caret went to the left on its own, and that was two separate faults.** The re-focus that follows a click
re-applied the first click's "select all", so the selection came back 140 ms later and again for nearly a second —
typing replaced text you had already written. And both windows' channel-matrix grid cleared the document selection
on **every** release anywhere in the window, which emptied the field you had just clicked and left it deaf:
measured, a selection of `[2,2]` became `[0,0]` and typing stopped landing. The re-focus now only re-opens the
engine's editing pipeline and never moves the caret, and the grid clears the selection only while the grid itself
has the pointer.

Number and date fields are the one honest limit: the engine gives them no caret to place. The first click selects
their value — so typing still overwrites it — and the second click reaches the end of it by rewriting the value
in place.

## The LTC window is a table now

You sent a screenshot and asked for it *"bonito, ordenado, funcional, cómodo"*. What was wrong was not one thing:

- **Nothing was named.** Every box was unlabelled, so the only clue to what a field was for was its placeholder —
  which disappears the moment the field is filled. The list now has a column header that stays at the top as you
  scroll, and it shares one grid with the rows, so a column name sits over its own column to the pixel.
- **Every cue printed itself twice.** The shared row line showed the number, the time and the name, and the
  editing fields directly below showed the same three again. The fields come first now, under the names, and the
  shared line sits below them as the row's status strip — the time, the health of the cue and its own controls.
  In editing mode nothing is printed twice, and the time returns to that strip whenever you open the ✎ editor,
  because that is the one place it is live.
- **The toolbar wrapped.** The shift preview is a whole sentence and it shared one line with the list tools, so it
  wrapped the bar and moved Apply. The tools and the shift now have a line each, and the preview is one line with
  the whole sentence in its tooltip.
- **The header and the footer read as groups**: a rule before the readouts and before the transport, a width on
  the offset field (it was the widest thing in the header and pushed Go away from the drive it belongs to), and
  the three "add a cue" tools together.

**Two things were found while looking, and both were about Live.** In Live the window still showed the column
names for fields Live had put away, and it still offered each row's own ✎ ✕ ⧉ Lock buttons — the tools that change
the list, in the mode whose own button promises to hide them. Both are gone in Live now. A locked cue still says
it is locked: the state stays, the control that would change it is where the editing is.

## Also in this build

- **The application no longer carries any trace of the machine that built it.** The compiled binary held strings
  naming the build account and where the project lived; the bundle identifier was that account name spelled as a
  reverse domain. It is `com.wingcontroller.desktop` now — which means macOS treats this build as a **new
  identity for the microphone permission**: if you had allowed the microphone, allow it once more (System
  Settings › Privacy & Security › Microphone), and every later build keeps that grant.
- **The interface no longer travels inside the binary as readable text**, and the symbol table is stripped: the
  windows are encrypted at build time and served through the application's own loader. The honest limit is in
  `docs/BINARY_PROTECTION_PLAN_2026-10-09.md`: the key has to be reachable by the code that decrypts it, so this
  makes copying the application expensive rather than impossible.

## What was measured, and what was not

- The click rule is asserted with **real mouse events** in all five windows: one click leaves the whole value
  selected, two leave the caret at the end, three leave it where you pointed, and the re-focus after a click never
  puts the whole selection back. Each of those four defects was put back by hand and the contract failed naming it.
- The LTC window passes its whole browser contract, including the two that measure the **rendered** layout: every
  column shares its x across the rows, no row wraps, and every field is a well in the kit's number type, in both
  themes. The design kit's own conformance suite reports `CONFORMANCE OK · 0 failures`, and the recorded
  screenshots of both themes were refreshed with the change.
- The `./scripts/verify-all.sh --quick` gate is green (43 checks). The **full gate** still reports the four
  browser suites that were already red before this work and are not this build's (field validation's 420 px
  popover, the meter bank selector, the meter bridge's dim colour and the Timecode clock's layout); each was
  re-run against the previous revision and fails there identically.
- **Not measured**: how the packaged window looks on your screen. The application's own web view cannot be driven
  from a test, so every claim above is about the files this build ships, rendered in the same engine family.
