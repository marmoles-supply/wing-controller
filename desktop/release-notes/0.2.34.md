# WING CONTROLLER Desktop v0.2.34

Build: 20260922.7 (macOS Apple Silicon)
Date: 2026-09-22

Two things: the **history graph** no longer discards data, and the **app icon is no longer a manual
step**.

## The graph samples at the refresh rate, not at the scroll speed

The symptom was that the *Win95 Task History* style graph still looked coarse and **gained no detail when
the speed was raised**. The cause was concrete: the sampling interval was calculated from the scroll speed
(`1000 / currentGraphSpeed`), so at 5x only **5 samples per second** were kept and **the packets that did
arrive were discarded**. Raising the speed added no data, it only squeezed the same ones.

Now they are two independent settings:

- **Refresh rate** (5 to 120 samples per second): how often a sample is taken and the graph is redrawn.
  Measured in the bridge window: **120/s → 106 samples in one second**, 30/s → 28, 5/s → 5. Before, it was
  a fixed 5 at 5x.
- **Scroll speed** (1 to 10): how many seconds of history fit on screen (12 s at 1x, 1.2 s at 10x).

The controls are **in the Meter Bridge window** (two sliders, `Refresh` and `Scroll`, visible with the
graph style) and **in Settings → Audio Displays** (the refresh rate goes from a drop-down to a slider,
with the scroll speed next to it). Both write the same preference (`wing_graph_refresh_fps`), and if the
old key in milliseconds exists it migrates on its own.

## The icon is no longer a manual step

macOS 26 puts app icons into its "squircle" and composes a background behind the artwork; the `Assets.car`
from `actool` does not avoid it and changing the icon appearance only **recolours** the tile. The only
thing the system does not re-shape is a **custom icon**; the problem is that it is Finder metadata: it
cannot go in before signing, and any `xattr -cr` erases it.

- **The build applies it and checks it** right after signing (and afterwards it verifies the executable's
  signature, which stays intact). As the icon survives the DMG cycle, **the artefacts ship with it
  already**.
- **The unlock restores it**: the `.command` that travels in the DMG and in the ZIP runs the helper (which
  also travels inside) **after** its `xattr -cr`, which is precisely what erases it.
- **Checkable at any time**: `./scripts/set-custom-icon.sh --check "/Applications/WING CONTROLLER.app"`.

And a real fault that came up while verifying the cycle: the helper's "the app is running" check used
`pgrep -f`, which matches **any** open copy of the app (for example the one on the mounted DMG), so it
refused to apply the icon precisely during the unlock. It is now anchored to the full path, and the
verified cycle is: `xattr -cr` erases the icon → the helper puts it back → `--check` says `[ok]`.

The whole rationale, with the measurements (3.9 % dark pixels with our own icon against 72.2 % for the
system tile) and the honest price of signing, is in `docs/ICON_MACOS26.md`.

## What to try

1. **The graph**: set *Refresh* to 120/s and *Scroll* slow. The trace must be dense and slide; if you drop
   the refresh to 5/s it must look clearly poorer. They are independent settings.
2. **The icon**: install from the DMG and run the unlock. The marble W must remain **without a tile**,
   without you having to do anything else.
3. **The VUs** in the Meter Bridge and in the side column: the same instrument.
4. **The desktop**: diagonal ramp, and the seam between blocks in the background colour.

## Corrections from the 2026-09-22 audit

- **"It verifies the executable's signature, which stays intact" needs qualifying**: with the custom icon,
  `codesign --verify --deep --strict` complains **about the bundle and the executable**
  (`resource fork, Finder information, or similar detritus not allowed`, exit 1) because of the `Icon\r`.
  The build treats it as an informative warning and checks the ad-hoc signature, which is what is actually
  verified; the app starts the same. See `docs/ICON_MACOS26.md`.
- The tab is called **Meters & Popups** ("Audio Displays & Meters" is the legend of the block).
