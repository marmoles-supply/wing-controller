# WING CONTROLLER Desktop v0.2.86

Build: 20261005.8 (macOS Apple Silicon)
Date: 2026-10-05

## The chase cannot freeze the window, a dead input says so, and one control brings it back

**Three CoreAudio commands no longer run on the main thread.** Listing the LTC inputs, reading the input
state and opening a stream were plain synchronous commands, so they ran inside the webview's own callback -
and opening one can wait ten seconds for a device. While that ran, every other command and every panel
waited behind it. All three are asynchronous now and hand their blocking work to a worker thread, with a
source contract that fails if any of them goes back.

**A stream that dies is a fact, not a silent hope.** A hot unplug used to print one line to a log nobody
reads while the window kept saying "Listening to …": the flag the interface asked was never cleared, and
nothing was emitted. The handler is now a named function a test can call, it clears the flag, records the
reason and emits an event, so the page can say what happened instead of the opposite of the truth.

**One control recovers without a restart.** "Reconnect the input" resolves the device again by name with a
fallback to the default, closes the old stream with a bounded wait, and uses a generation counter so an
error from the retired stream cannot speak for the new one. It says what it is doing before it waits.

**And the refusal that looked like a broken feature now says what to do.** A macro whose trigger is half
set is still refused - that rule is right - but the message named the action target, which is a different
problem, and never mentioned the one thing that fixes it. It now names the remedy and points at the WHEN
panel, and the advice quotes the editor's own label rather than repeating it.
