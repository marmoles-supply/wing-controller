# WING CONTROLLER Desktop v0.2.84

Build: 20261005.6 (macOS Apple Silicon)
Date: 2026-10-05

## 24-bit LTC recordings are read

The reader accepted 16-bit PCM, 8-bit PCM and 32-bit float, and **refused 24-bit PCM** - the most common depth for a
recording of timecode. It is read now, with the sign extended before scaling, which is the part that matters: without it
every sample above half scale reads as a large negative number, and a defect like that does not fail, it decodes wrongly.

The suite had a test that **asserted the hole** - "24-bit is not read" - and it was deceptive as well: it declared 24 bits
in the header while writing 16-bit samples, so it would not have read correctly even once the depth was supported. It is
replaced by one that writes real 24-bit samples and requires two things of them: that they survive to within one step of
the depth, and that they keep their sign. The refusal it used to cover is now tested against 32-bit **PCM**, which is a
depth this build genuinely does not read and is not the same thing as the 32-bit float it does.
