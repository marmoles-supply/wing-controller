# WING CONTROLLER Desktop v0.2.89

Build: 20261005.11 (macOS Apple Silicon)
Date: 2026-10-05

## The timecode input rate applies itself, and stops being able to be wrong in silence

Changing the rate used to do nothing to a running stream: the input is opened with the rate of that moment, and nothing
reopened it, so an operator whose material is 30 fps and whose selector said 25 kept decoding at 25 - and the cues ran
late with nothing on screen to explain it. Changing the rate now reopens the input by itself, saying what it is doing
before it waits and naming the step if the reopen fails. The rate control has also moved out of the file-verification
group, where it read as the rate of the file being checked, to sit with the live input it actually governs.

And a wrong rate is no longer silent: when an open input has decoded no timecode position at all since it opened, the
status line says so, names the rate in use, and points at the rate and the channel. A stream that merely stopped is not
blamed on the rate.

## A cue shows its courtesy notice, and adding a cue at the end is one press

A macro fired by a cue showed no courtesy notice even with the toggle beside `enable` switched on. All firing paths now
read that one setting; a cue passes what it is - the macro fired by a cue, and the cue's position - while the context
menu's Fire Macro stays silent, because the operator just pressed it.

`Add cue at the end` appends one frame past the latest position in the list - not the last row of the array, so it lands
last whatever the ordering - and adding does not move what the operator was looking at, which matters when a show is
thirty cues long.
