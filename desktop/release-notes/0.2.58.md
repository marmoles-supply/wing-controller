# WING CONTROLLER Desktop v0.2.58

Build: 20260927.3 (macOS Apple Silicon)
Date: 2026-09-27

The backend now answers what the session is instead of making the windows infer it from events, the
console's own measurements are what the code says, the macro list stops rebuilding under the operator's
hands, and the meter bridge can tell a refusal from a link that went away. This build follows 0.2.57 the
same day.

## The backend's state is managed, and the windows ask for it

`app.manage(BackendState)` and a new `get_stream_state()` command answer `state`, `message`,
`sessionActive`, `sessionId`, the desk's model **family**, the live-safe mode, `health` (null unless a
session is really live), the meter sources, whether the meter bridge is open, and the last alert with
whether it was delivered. Both windows ask on start-up and after a reload and paint that answer, instead
of reconstructing the session from events they may have missed — which is what made an OFFLINE badge on
a live stream, a health grid frozen with the last numbers, a bridge line contradicting its own badge and
a HUD alert shown by nobody possible. A meter frame now carries the session it belongs to, so a window
cannot paint a quarter of a second of the previous stream in the new one.

## The console's own answers, in the code and in a command

Everything the documents left open was measured against a connected console and the results are now what
the application does: the monitor level's write is offered only where the desk takes it (the full-size
console and the Rack refuse every form — measured — and only the Compact keeps it), an FX slot that holds
no model says so rather than looking silent, the safes node keeps its hardware-confirmed spelling, the
`/cards/wlive/*` report leaves that stay silent without a card stay out of the catalogue, and the meter
group lengths of the family are recorded with the one case a rack cannot measure named as such.
`scripts/wing-hardware-checks.mjs` asks any console of the family the same questions in one command.

## The macro library stops rebuilding, and its counters follow the macro

A runtime event used to rebuild the whole list: the scroll jumped to the top and an inline rename was
destroyed. The affected row is patched in place now, and a row being renamed is left alone. The counters
follow the macro's own identity (the one the console compiles) rather than its position in the list, so
reordering or deleting can no longer show another macro's numbers, and a deleted macro's counters are
forgotten instead of accumulating for the session.

## The meter bridge says what its link is doing

A drop used to read "Cannot reach console" whether the console had refused, the link had gone or the desk
was rebooting, with a retry every two seconds and no counter. The bridge now says `● LIVE LISTENING`,
`● DROPPED · RECONNECTING n`, `● CONNECTING · RETRY n`, `● CANNOT REACH CONSOLE` or
`● CONNECTION LOST` (when the dock's auto-reconnect is off), with the wait since the drop and the attempt
number in the status line — and a failed retry after a link that was live stays a reconnection, not a
refusal. A window saved on a screen that is no longer connected comes back on a screen that exists.

## Small things, from the plan's own polish list

Informative confirmations lost their second button; the empty magnifier in the search field is a real
icon; the dither pattern cache is bounded (64 entries / 12 MB, `WingDither.cacheStats()`); the dead
resizer transition is gone; the dock's matrix position no longer shares a key with the bridge's; a
mis-spelled dialog option that was silently ignored is fixed; the disabled look exists in both themes.

## Verification

every step green, including the browser suite that now starts, rotates and restarts its own Chrome. The
