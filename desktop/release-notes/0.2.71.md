# WING CONTROLLER Desktop v0.2.71

Build: 20261004.1 (macOS Apple Silicon)
Date: 2026-10-04

This version exists because the owner tested 0.2.70 and reported exactly what was wrong with it. Four things that did
not work now work, three things that were promised but hard to find are where they belong, and everything has
instructions.

## What was broken, and why

- **"Add an application" did nothing.** The backend refuses an application row with no name, and the button created
  one with an empty name, so every save was refused. It now creates a row with a starting name that is meant to be
  edited.
- **The audio input could not open.** Two different things are required for a microphone on macOS: the `Info.plist`
  carries the description the system shows, and the **entitlement** carries the right to ask. Only the first was
  there — so the devices were listed and then the input refused to open. Both are declared now, and the gate refuses
  a build that has one without the other.
- **Refresh appeared to do nothing.** It now says what it asked, what came back, and why our own MIDI ports are
  absent until the switch is on and they are opened. The audio list also stopped swallowing its own errors: "there
  are no inputs" and "the inputs could not be listed" are different sentences.
- **The clock could not be popped out.** There is a **Clock** button in the toolbar beside **Meters**, and the new
  Timecode card has the same **⧉ Popout** the meters card has.

## What is new

- **Two cards in the right-hand column**, where an operator actually works: **Timecode (MTC, LTC, SMPTE)** with the
  position in the application's own CRT readout, its state and the next cue; and **MIDI, Inter-app OSC** with the
  switch state, the ports and the listener.
- **MIDI and timecode in the macro editor**: under the trigger signal there is now a block that lists the bindings
  which fire the macro on screen, and buttons that make one — a MIDI binding with a first guess to **Learn** over, or
  a **timecode cue at the position the show is at right now**.
- **The tabs are named properly**: **MIDI, Inter-app OSC** and **Timecode (MTC, LTC, SMPTE)**.
- **Instructions, both places**: each page opens with a folded **How to use this page (step by step)**, and the guide
  gains **chapter 12 · MIDI and other applications** and **chapter 13 · Timecode (MTC, LTC, SMPTE)**.

## What still has not been proved

The audio input's live path has never seen a real signal — the codec is proved by generating LTC in its own tests. On
a machine whose only input is the built-in microphone there is nothing that carries LTC, so this needs an interface
or a virtual audio device (BlackHole, Loopback) at the desk. The Mixing Station acceptance pass is still unrun, and
RTP-MIDI is still researched rather than connected.

One thing worth knowing when running the test suite rather than the app: the MIDI transport tests cannot pass while
this application is open, because it holds virtual ports with the very names they create. The failure now says so
instead of saying *timeout*.
