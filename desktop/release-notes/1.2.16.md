# WING CONTROLLER Desktop v1.2.16

Build: 20260921.3 (macOS Apple Silicon)
Date: 2026-09-21

## Protocol: writes that used to be silently ignored

The console was ignoring several macros without telling anyone: the app reported
success while nothing happened. All of these are fixed and were confirmed on
hardware with read-only leaf reads.

- **Gate and compressor thresholds** resolved to `/gate/thr23`, `/dyn/thr26`,
  `/dyn/thr37`, `/dyn/thr42` and `/dyn/thr46`. Those trailing numbers are footnote
  references in the protocol document, not path segments; the console only knows
  `/gate/thr` and `/dyn/thr`. Every family now uses the real path.
- **EQ** offered bands 5 and 6, which the STD channel EQ does not have, and could
  not reach the low and high bands at all. Bands 5 and 6 are gone and the low and
  high bands are now automatable: `/eq/lg`, `/eq/lf`, `/eq/lq`, `/eq/hg`, `/eq/hf`,
  `/eq/hq`.
- **Aux** offered filters and gate parameters the console does not have. Aux
  exposes no filter node and no gate node; both are no longer offered. Everything
  aux really has is kept and verified: EQ, compressor, fader, mute, trim, phantom,
  phase and alt source.
- **Main** offered sends, but main strips have no numeric send node. Sends remain
  for channels, aux and buses.
- **Oscillator sources** offered polarity, which does not exist on them. Polarity
  remains for the sources that have it, such as local and USB.
- **Snapshot and preset loading** pointed at `/show/load` and `/library/load`,
  which do not exist: loading a snapshot is a console filesystem operation, not an
  OSC address. They now fail validation explicitly instead of pretending to work.
- **Parameter ranges** now follow the documented values, so validation can no
  longer accept a value the console would refuse.

## OSC state correctness

- The state cache stored the rounded text rendering of a parameter instead of its
  value. A fader at -21.752 dB was cached as "-21.8".
- The console reports state only when it changes and never re-publishes it when a
  subscription is renewed, so a single lost packet left a condition wrong forever.
  The app now re-reads every address used by a trigger or condition on a rotating
  basis, which is authoritative and costs at most one packet per 500 ms taken from
  spare bandwidth, so it never delays metering.

## Safety and stability

- A saturated OSC send queue no longer aborts the live stream. Previously a burst
  of macro traffic could take the whole session down mid-show.
- An action interrupted by Panic Stop or by the stream ending (network timeout,
  meter stall, disconnect) is reported as **aborted** instead of **failed**, so the
  failure counter no longer fills with runs that were stopped on purpose.

## Editor and interface

- The **1-9** hotkeys now select the macro in that position; they had been dead.
- The library inspector now shows the real action count, threshold and overlap
  policy instead of a default.
- The meter context menu's **Win95 History Graph** actually switches to that style.
- **Verify WING Identity** in the OSC terminal now performs the real identity
  probe instead of calling a command that does not exist.
- The **About** dialog credits Patrick-Gilles Maillot for the WING Remote Protocols
  documentation this application is built on.

## Validation boundary

- Metering was validated read-only against a real WING Rack: 48 USB values, 49 for
  a mixed collection, and 878 values across all 16 Source and 11 Output groups.
- Every path change above was verified by reading the parameter on the console.
- **Not validated on hardware in this build**: macro action dispatch, consecutive
  triggers, reconnection and a long soak. Treat this as a beta for rehearsal and
  preparation, and keep a manual path to the console for anything show-critical.
- Parameters whose existence depends on the model loaded in a strip's dynamics or
  EQ slot (a channel running `DEQ2` has no gate threshold) are still offered
  regardless of the current model. That is the next protocol workstream.
