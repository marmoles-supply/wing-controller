# WING CONTROLLER Desktop v0.2.53

Build: 20260925.1 (macOS Apple Silicon)
Date: 2026-09-25

The macro target list is grouped, a bus can no longer be offered a send to itself, a write the
console ignores is reported instead of counted as done, and the windows can no longer be lost. Two
independent adversarial reviews — one over the code, one over this documentation — then found
defects in that work, and this build closes them.

## The target list is grouped

The picker was one flat list of about a hundred keys, so the targets added in the last build —
matrix sends, main sends, insert slots — could not be found. It is now a menu grouped as **Meter ·
Level & routing · Sends** (with **Bus sends** 1…16, **Matrix sends** 1…8 and **Main sends** 1…4)
**· Input · Filters · EQ · Gate · Dynamics · Insert · FX · Output & routing**, with submenus that open
on hover, on keyboard focus and on click. Only what the selected strip has is listed, and a submenu
stays inside the window whatever its width.

## A bus is never offered its own send

The console ignores a bus that sends to itself, so that index is shown as unavailable with the
reason, and a stored macro that points there is refused by Save, Arm and Shoot with the same sentence.

## An ignored write is reported

Only numbers used to be read back, so a model name, a tap or an insert slot could be written to a path
the console ignores while the macro counted as completed. Every write that carries a value is now read
back and compared — numbers with the documented tolerance, `true`/`false` as 1/0, everything else as
trimmed text — and a fade is checked once at its end. A mismatch is something the operator reads,
never a failed step, and the read-back is bounded: it retries a 60 ms leaf read inside a 250 ms
settle budget, so a step costs at most about that.

## The strip's model is consulted before the write

A gate, compressor or EQ name belongs to the model loaded in that strip's slot: a `DEQ2` gate has
`1-thr`, not `thr`, and a `WARM` compressor has no `thr` at all. The editor reads each strip it is
pointed at, carries that model with the target — for the `gate:1-thr` spelling and for the plain
**Gate Threshold** key alike — and a name the model does not have is refused with a message that names
the model and a few names it does have. Each panel is read for its **own** strip: the step, the
trigger and every IF gate carry the model of the strip they address, never another panel's. A save
keeps the model the macro was **written for**, so a macro written for one model is not silently
rewritten into another. A file that carries no model keeps working, with the note that the model was
not checked.

## Windows cannot be lost, and can be brought back

Preferences and the Channel Matrix Selector are dragged by their titlebar, and their remembered
position was restored verbatim, so a dialog last placed on a bigger screen came back with its titlebar
off screen and no way to grab it. One clamp now covers the drag, the remembered position and a resize,
and **Settings → General → Re-centre windows** centres both dialogs, forgets the positions they had
remembered, and brings the Meter Bridge and the Guide back on screen — saying exactly what it moved,
what it only forgot, and when nothing needed doing.

## Compact density no longer collides

In the compact layout the macro row pinned NOTICE to the 20-pixel box it had as an icon while the word
needs 36, so the label spilled over ENABLED; the three secondary controls keep the compact height and
take their width from their label, a long name ellipsises, and the grouped picker's rows grow around a
wrapped label instead of painting it outside their box.

## What the reviews found, and this build fixes

The serious ones. The model check only looked at the `gate:1-thr` spelling, so a macro on the plain
**Gate Threshold** key escaped it — the same names are checked through the catalogue now. The model
that travelled with a trigger or a gate was the **target strip's**, so a valid macro could be refused
naming a model it would never run, and the reverse passed the check while the console ignored the
write. A trigger on a name with no value typed silently became `name == "1"`: it armed and could never
fire. A meter index above its family's count (`ch 100`) could be armed. Colour, icon, compressor knee
and output index are written as the whole numbers the console documents, and no longer offer a fade.
The Shoot button, preflight and the compile path now agree on a raw custom address; a `/meters/` action
cannot be armed; a PANIC STOP during a read-back is no longer reported as a verification failure; and
a pasted en dash in a channel list is read as the range it looks like.

The documents were wrong in nineteen places, including two that promised what the app does not do (a
matrix's direct input that no key offers, and a specification that had already shipped). They now
describe the code as it is: the per-destination send range, matrix sends as reachable, `trim` and
`phase` on every mix family, the bounded meter index and the read-back's real cost.
