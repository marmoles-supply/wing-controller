# WING CONTROLLER v0.2.81

Build: 20261005.3 (macOS Apple Silicon)
Date: 2026-10-05

## A button that cannot answer must not be silent

The Timecode section's **Refresh** and **Ask macOS for microphone access** could stop doing anything at all, while the
rest of the window kept working. The handler had its error path: what happened was that the call never came back. A
promise that neither resolves nor rejects runs neither the code after it nor its catch, so the line stayed silent and the
refresh below it never ran - and the section looked dead.

Both paths that touch CoreAudio are now bounded, and both **say what they are doing before they wait**. If the system
never answers, the line says so, names the setting to check and tells the operator to press Refresh. Listing the inputs
is bounded too, because it goes through the same CoreAudio permission.

Nothing here changes what the feature does when the permission is already granted: it is the silence, not the asking,
that was the defect.
