# WING CONTROLLER Desktop v0.2.59

Build: 20260927.4 (macOS Apple Silicon)
Date: 2026-09-27

A run now says which step failed instead of only how many, exports and imports ask you where the file
goes, the FX parameter list learns the slot's model from the desk, and the workstation window remembers
its own size and place. This build follows 0.2.58 the same day.

## A run says which step failed

The run result reported a count of writes the console did not confirm, which left you hunting through
the timeline for the row that did it. Every step of a run now carries its own state:

- **confirmed** — the console holds the value that was sent.
- **unconfirmed** — the read-back did not match, or the desk never answered.
- **not verifiable** — a wait, a notice, a write-only command: nothing to read back.
- **interrupted** — a stop you asked for ended the run around it.
- **not attempted** — the run never reached it.

The step the console did not confirm is marked on its own row in the step list, with the run's own word
for it in the ScreenTip, and a run the console confirmed clears the mark. A stop you asked for never
leaves that mark, because it is not a write the desk refused, and a write the run never sent is never
shown as one that failed. The log line of an ignored write names the step it came from as well.

## Exports and imports ask you where the file goes

*Export Show JSON* and *Import Show JSON* open the system's Save and Open panels now, exactly as the
station backup does, and the macro library's export and import commands do the same. Closing the panel
without choosing changes nothing and reports nothing: it is not a failure. Only when the panel cannot be
shown at all does the file go to a `WING CONTROLLER` folder inside your Downloads folder — the folder
the system itself reports — and the window tells you the path it really got. Nothing is ever written to
a folder assembled from your home directory again, and an export no longer leaves a `.bak` copy beside
your file: that copy belongs to the app's own data files.

## The FX parameter list knows which model the slot runs

Naming an effect's model by hand was the only way to see its parameters, although the console knows the
answer. The app reads the slot when you point the panel at it — one round trip per slot, once per visit
to the category, never per keystroke — and the field fills itself with what the desk answered. An empty
slot says so, a slot that stays silent leaves the manual field as your fallback, and a model you typed
is never overwritten: the line under the field tells you what the console reported instead. The answers
are read again when you come back to the category, because that is where an effect is loaded.

## The workstation window remembers its box, and the simulation library does not travel

The window comes back at the size and in the place you left it — and a place that no longer lands on a
screen you have is dropped, so it opens centred instead of off-screen. *Re-centre windows* in
Properties → General forgets it too.

The browser-mode simulation library used to ride the macros section of every station backup, so a file
you sent to a colleague carried macros you never wrote. It is not part of the station: it is neither
exported nor written back by a loaded file.

## Smaller, in the same round

The three diagnostics under *Probe* (metric frame, trigger self-test, decode stress) say in the panel
that their answers are simulated, so a synthetic reading cannot be taken for a reading of your desk;
only *Verify Targets* reads a console, and its tip says so. The collapse chevrons and seven small labels
were 8 and 8.5 px, below every other size in the window: they are 9 px now, measured not to clip
anywhere. The FX model read keeps only the last 32 slot lists of a visit, so nothing in the panel grows
for the length of a session.

## The guide, corrected

The guide still promised that both explicit exports were written to `~/Desktop` with no picker and that
the simulation library travelled in a backup. Chapter 6 and the troubleshooting chapter were corrected,
including what the workstation window and the bridge do with a remembered box, and the published guide
was rebuilt from them.
