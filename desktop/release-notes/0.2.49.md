# WING CONTROLLER Desktop v0.2.49

Build: 20260923.2 (macOS Apple Silicon)
Date: 2026-09-23

The macro list now saves a show: a **Show** box with its name, **Save…** and **Load…**, the saves
folder renamed to match, and the show name travelling inside the file.

## The Show box

The two buttons next to the macro list are now a box titled **Show**, with three parts:

- **Name** — the show you are working on: up to 40 characters, spaces and all, kept in one place and
  mirrored into the Properties panel.
- **Save…** — asks what the file carries (macros and meters ticked, which is what a show needs) with
  the name already filled in, then opens the system Save panel. If the panel cannot be used, the file
  lands in the show folder and the notice says so.
- **Load…** — the file picker, then which of its sections to apply; when the window comes back it says
  what it restored.

The line under the buttons says which show is open, when it was last saved, where the file went and
whether anything has changed since. If it says there are changes, closing the app warns you before
quitting — and it no longer warns only about unsaved macros.

## The show name lives inside the file

A backup carries `show: { name, savedAt, scopes, appVersion }`, so a file that has been renamed, mailed
or copied off a USB stick still says which show it is, and loading it puts the name back in the **Name**
box. The dialog that asks which sections to apply shows both sides of the file's identity: **its name on
disk** and the **show name written inside it**, with when it was saved and the version that wrote it. A
file from an earlier version, which carries no such metadata, says so instead of showing a blank.

## The folder is `Documents/WING CONTROLLER shows`

Matching the show wording everywhere else. An existing `WING CONTROLLER backups` folder (0.2.48) is
renamed to it on first start, so the shows saved with the previous build stay where you look for them.
The app log is `logs/shows.log`.

## A restore is all or nothing

Everything that can fail — the macro library and the draft written to disk — happens **before** a single
stored preference is touched. If any step fails, the preferences are put back exactly as they were and
the dialog says which step failed, instead of claiming that "nothing was changed" while something had
been. A file that declares a section it does not carry, or whose macro entries are not macros, is
refused before anything is written.

## A `.wingstation.json` can no longer run code in the window

Meter labels and keys restored from a file reached the window's HTML without escaping, and the window
has no CSP: a hand-made file could execute script, and the application's own file-writing command was
within reach of that script. Every value that comes from a file is now escaped where it is rendered —
the same treatment the Meter Bridge already had. The application's own state (the show name, the save
folder, the ticked sections, "already saved") is also refused on the way in, so a hand-edited file can
no longer silence the closing warning or point the next saves somewhere else.

## Also in this build

- Saving is harder to interrupt: the temp file is unique per process and flushed to disk before the
  rename, a save that cannot use the chosen place falls back to the show folder instead of giving up,
  and a **late answer to the abandoned Save panel is no longer thrown away** — the file is written
  where the operator chose and the log records it.
- A save that replaces a file from earlier the same day says so in the confirmation.
- The ticked sections are remembered for the next save; the Inspector describes the new controls.
- Every comment and every build message is now in English, including the text the build prints and the
  helper that ships inside the DMG.

## Verification

`./scripts/verify-all.sh`: **39 checks** — TypeScript, syntax of the three windows, 35 Node tests
(18 of them driving the real UI in Chrome), the strict Maillot path audit and `cargo test --workspace`
(152 Rust tests including the three new ones for the folder rename).
The backup test drives the whole flow: saving with the panel, without it, the fallback folder, the
contents dialog, the Show box, the show name inside the file, the load dialog's metadata, a
hand-written frozen file, a file that forges the app state, a file that claims a section it does not
carry, and the closing warning.

## What to try

1. **Properties → Profiles & Backup**: the line must say **`Running WING CONTROLLER 0.2.49 (build
   20260923.2)`**, and in Finder `Documents/WING CONTROLLER shows` must already be there.
2. **Next to the macro list**: type a name of two words in **Name** (the space must stay), press
   **Save…**, tick macros and meters, and save. The notice must give the path and the file must be
   named `wing_<show>_<date>.wingstation.json`.
3. **Load…** on that file: the dialog must show the file's name and `Show: "<name>"`, and after the
   reload the report must be titled `Show "<name>" restored`.
4. Close the window without saving a backup: it must warn that the show is not saved.
