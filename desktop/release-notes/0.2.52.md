# WING CONTROLLER Desktop v0.2.52

Build: 20260924.2 (macOS Apple Silicon)
Date: 2026-09-24

A macro can now reach the sends, insert slots and strip controls the console actually has — and it
can no longer be given a comparison that cannot work. A sweep of every OSC node the protocol
document defines found both.

## A comparison that cannot work is no longer offered

A trigger on a source's **Name** arrived with the comparator "rises above" and a dB threshold. Text
has no size, so the comparison could never be true: the macro saved, armed and **never fired**, with
nothing said. The same family covered on/off parameters offered with a dB threshold and frequencies
labelled dB.

- **Every parameter carries its kind** — meter level, on/off, number with a unit, text — and the kind
  decides what can be compared with it and which value is asked for:

  | Kind | Comparison | Value |
  | --- | --- | --- |
  | Meter level | rises above / falls below | dB |
  | On/off (including the V2 gate LED and dyn state) | equals / not equals | ON or OFF |
  | Number with a unit | is above / is below / equals / not equals | a number, with its unit and range |
  | Text (a name, a model, a mode, a tap) | equals / not equals | the text itself |

- **The rule lives in one place and is enforced twice**: the editor builds its lists from it, and the
  backend applies it in preflight *and* in the path that compiles the library for a live session, so a
  hand-edited show file cannot inject what the window would refuse. An unknown comparator is
  normalised to `>`, and the parameter's kind then judges it: on a text, on/off or closed-list
  parameter `>` is not allowed, so it is refused.
- **The Edge selector only appears where it means something** (state parameters). In a meter trigger
  the comparison already names the crossing, and the two used to contradict each other.
- **A fade is only offered for values that can be ramped**: it writes numbers, so it is hidden for a
  mute, a name or a model. "Automation cue" is now "Smooth fade" — a client-side ramp, because the
  console has no cue path.
- **An index outside the family is refused** (`ch 999` resolved to a path the console ignores while
  the app reported success) and a step that targets a model parameter is no longer rewritten to
  `mute` when you look at another step and come back.

## The sends a macro could reach were only half of them

Bus sends (level and on/off) were all the catalogue offered. A step can now set:

- a channel's, an aux's or a bus's **matrix send** (1…8) and **main send** (1…4), with their on/off and
  pre/post switches;
- the **tap of any send**: `PRE`, `POST` or `GRP` on channels and aux, pre/post on buses and mains;
- a send's **pre always on** and a bus send's **pan**.

The index is bounded by what it addresses — 16 buses, 8 matrices, 4 mains — and the field is labelled
with it. A matrix has no sends at all and a main has no numeric bus send in the protocol, so neither
is offered; a bus sending to itself is refused with the reason (the console ignores it silently).

## Inserts and FX

- An insert can now say **which FX slot it holds** (`NONE`, `FX1`…`FX16`), and a channel's post-insert
  its mode (`FX`, `AUTO_X`, `AUTO_Y`) and autogain weight (±12 dB). The hint warns that assigning a
  slot to an insert takes that effect away from the strip it was plugged into, and that every insert
  adds about 32 samples (0.66 ms) of delay.
- The **FX model is a closed list per slot** instead of free text: slots 1…8 load all 65 documented
  models, slots 9…16 the 39 effects-only ones, so a typo can no longer be written and silently
  ignored. A model that the chosen slot cannot load is refused before the write.
- A model's own parameters stay out of the catalogue on purpose: their meaning and range depend on
  the model loaded in that slot. Use a Custom OSC step with the raw address for those.

## Strip controls that were missing

Width, input delay (on, mode and time), monitor mode and solo safe, each bounded by the documented
range. The delay's value is in the unit its mode selects (metres, feet, milliseconds or samples).

## Four protocol defects fixed on the way

- A **trigger or an IF gate on a send** carried no destination and aimed at send 1 in silence; for
  bus 1 that is the self-send the console ignores. Both now carry their own index or fail closed with
  the reason.
- The **output-source list was not the documented one**: it invented `INP`, `USBREC` and `SIG` and
  dropped `USR`, `SEND` and `MON`, so the editor offered `output_group = SEND` while the validator
  refused it.
- **`2250`** was missing from the gate and dynamics model lists — the generator dropped the only
  all-digit model name — so a model the console has could not be selected.
- **User controls**: the editor offered sixteen buttons where the console has four on the first page,
  so ids 5…16 built a path that does not exist.

## Documentation

`docs/MACRO_TARGET_COVERAGE.md` records the sweep: every family the protocol defines, the line it is
documented at, what a macro can do with it today, and the controls that are still not offered —
highest value first (scene recall, solo, talkback, GPIO, input routing, the USB recorder and player,
