# WING CONTROLLER Desktop v0.2.99

Build: 20261020.1 (macOS Apple Silicon)
Date: 2026-10-20

## The design kit is approved, and the five windows share one production chrome

This release carries the reviewed design-kit work: the production workstation material is now a
distributable kit, and the Workstation, Meter Bridge, clock, LTC cue window and guide all draw the same
raised chrome, panels, wells, controls and type scale. The kit is version **1.5.0**, independent of the
desktop version.

The kit contains the production chrome (`workstation.css`), extracted surfaces and states
(`surfaces.css`), the byte-identical dropdown, field-editing, dither and VU runtime modules, a working
template and interactive catalogue, a manifest-validating project creator and a canonical-chrome checker.
The older three-sheet specimen and `reference-window` remain for existing consumers; they are labelled
historical and are not the target for a new WING-equivalent page.

### The cue row follows the kit's scale

The shared cue row was the last surface with fixed pixel type: 9.5, 10, 10.5 and 11 px text and 18 px
controls. It now uses the kit's `--font-base`, `--font-sm` and `--font-xs` steps, and its controls have a
minimum height rather than a fixed one, so a larger `--meter-scale` grows the row instead of clipping it.
The number track is derived from the same step, so a numbered row and a row without a number keep the time
in the same column. The rules are scoped under the row so the shared chrome cannot resize a row differently
in the LTC and clock windows. The compact 420×200 clock and its one-row floor are unchanged; the browser
contracts measure 18 px at the default scale, growth at scale 2, and the numbered/unnumbered alignment.

### The guide names all five windows

The guide's opening chapter said “The two windows” and described only the workstation and the Meter
Bridge. It now names the five: the workstation, the Meter Bridge, the clock, the LTC cue window and the
guide, with how each one opens. The generated guide content was refreshed with the chapter.

### Settings reach their controls from every route

The Timecode controls are bound once at startup, so opening Properties from a Timecode card shortcut no
longer arrives before its handlers. Page polling follows the active page and stops when the window closes.
The Settings categories are real tabs with arrow/Home/End navigation and roving focus; opening the dialog
transfers focus inside, Tab is contained while it is modal, closing returns focus to the opener, floating
mode updates its modality, and the child scope pickers consume Escape. The matrix keyboard pass remains a
separate item and is not claimed here.

### LTC header

The LTC window's clock column no longer shrinks below its own SMPTE text, so the last frame digit is not
cut at a normal window width. The last-fired readout belongs to Live and is hidden before Live, where it
used to show an empty box.

### Kit review and evidence

The kit was reviewed in both themes at 420, 820 and 1280 px. Its own checker compared every required chrome
role and the common control variants against the canonical template; the paired screenshots were inspected,
and the checker now repaints the dither after a theme change so a light-theme image cannot carry the dark
pattern. An independent consumer was created from the final `wing-controller-design-1.5.0.tar.gz` outside
this repository: all 75 manifest entries verified, and the distributed checker returned 0 failures at all
three widths in both themes.

**Approved scope:** HTML/CSS/JavaScript consumers taking the complete kit, and these five desktop windows.
**Not covered:** arbitrary product workflows, native SwiftUI/Qt equivalence, OS-owned file/colour/permission
panels, live telemetry, or a machine other than this one. The screenshots are deterministic no-backend
frames; a green checker proves drawing parity, not usability.

## Known limits carried forward — R1 to R5 remain open

This release changes no Rust, protocol or execution source. The audit findings below were **not** fixed and
must not be read as closed:

- **R1:** overlapping manual or external runs can overwrite the single cancellation slot, so an older run
  can survive Panic Stop.
- **R2:** cancellation is not checked before every step type; a pre-cancelled sequence can still send a
  MIDI or OSC step.
- **R3:** external triggers bypass the macro overlap policy.
- **R4:** Custom OSC still offers Fade and Toggle modes that validation refuses for an unknown target.
- **R5:** restoring a station is not transactional; a later failure can leave a mixture of old and imported
  sections.

Until R1–R3 are repaired and accepted with overlapping-run tests, do not rely on Panic Stop to stop an
older overlapping run. The full decision, grounds and the condition that would overturn it are recorded in
`docs/PRODUCT_AND_DESIGN_KIT_AUDIT_2026-10-20.md` §"R1–R5 — evaluated for release, not fixed".

Other limits: no live console, real LTC/MIDI signal or native panel was used in this review; Android is
parked and was not built. The source gate does not drive the packaged WKWebView UI. The build was installed
and its installed copy was verified and launched for a spot-check; a full workflow inside the packaged UI is
still not driven by a test.
