# WING CONTROLLER Desktop v0.2.39

Build: 20260922.12 (macOS Apple Silicon)
Date: 2026-09-22

Scoped backups and a restore that can no longer lose anything.

## What was wrong

The station backup was all-or-nothing in both directions, and the restore was **destructive**: it wiped
**every** `wing_*` key before writing the ones in the file. Any preference the file did not carry — an
older backup, a partial one, a key added by a newer version — was lost silently. There was also no way to
export or restore just one part of the station.

## Scopes

Four groups, each independent:

| Scope | What it carries |
| --- | --- |
| **macros** | The whole library and the draft you are editing |
| **settings** | Appearance, shortcuts, safety, HUD, OSC, matrix… (the default bucket) |
| **meters** | Watchlist, custom banks, style, size, zoom, graph, peaks |
| **network** | Console IP, interface, strict mode, timeouts, reconnect |

Every preference belongs to a scope through an explicit table, and anything new falls into **settings**,
so a fresh preference can never be left out of a backup by accident.

## What changed

- **Schema 3 file** with one section per scope and a `scope` field declaring what it carries. A schema 2
  file is still accepted and is read as "carries everything"; a complete export still includes the flat
  schema 2 fields so an older version can read it.
- **Per-scope validation.** A file with a broken meter section is refused with the meter reason, not as a
  whole.
- **The restore never deletes.** It writes what the file brings, only for the scopes you pick, and leaves
  everything else exactly as it was. A file that is missing a preference can no longer make it disappear.
- **Pickers on both sides.** When exporting: four checkboxes plus *Select all* / *Select none*, and a
  warning if none is ticked. When restoring: a picker that lists what the file carries (with counts) and
  applies only what you tick.
- **A backup can no longer fail because of the draft.** If the builder cannot be read at that moment, the
  draft is skipped and logged and the file is still produced.

## Verification

`./scripts/verify-all.sh`: **32 checks** — TypeScript, syntax of both windows, 28 Node tests (12 of them
driving the real UI in Chrome) and `cargo test --workspace`.

The station backup suite covers the key classification, the schema 2 and 3 rules, the per-scope
validation and the guarantee that matters most: restoring one scope cannot touch the others. Five cases
run against a fake store, so no window reload is involved and the test cannot be flaky.

## What to try

1. **Export** with only *Meters* ticked: the file says so, and restoring it elsewhere leaves macros,
   settings and network alone.
2. **Restore** a full backup but tick only *Macros*: the rest of the station stays as it is.
3. **Restore an old backup** that is missing a preference: nothing disappears.
