# WING CONTROLLER Desktop v1.2.9

Build: 20260920.3 (macOS Apple Silicon)
Date: 2026-09-20

## Connection fix

- The WING identity handshake (`WING?` on UDP 2222) now probes each active local IPv4 address and retains the source-bound socket that receives `WING,...`. This fixes a Mac with Wi-Fi and Ethernet on the same subnet selecting the wrong interface.
- Native meter TCP 2222, native meter UDP return, OSC event subscription on UDP 2223, manual OSC sends and macro action sends all use the selected local source. Reconnect repeats route selection.
- Network discovery broadcasts separately from each local IPv4 address. The UI shows the console name, IP, firmware and selected local route, and fills the IP field without connecting automatically.
- Cancelling during connection stops before meter or OSC subscription where possible.

## Verification and boundary

- Maillot 3.1.0, "Remote communications with WING": `WING?` on UDP 2222, `WING,...` reply, OSC on UDP 2223. Maillot Channel 3 meter request and decode order/scaling were not changed.
- A WING Rack verified on hardware answered through the selected Ethernet adapter; targeted and broadcast discovery passed. Source-bound TCP 2222 opened and a read-only USB meter request returned 48 decoded values.
- Rust workspace, TypeScript, desktop JavaScript syntax, safety, reliability, HA and X32 tests passed.
- Macro actions, reconnect under cable loss, fast repeated triggers and a long soak were not tested against the console. Disable all macros and disarm the draft before the first app-level connection test. Do not treat this build as show-validated yet.
