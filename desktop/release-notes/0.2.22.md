# WING CONTROLLER Desktop v0.2.22

Build: 20260921.9 (macOS Apple Silicon)
Date: 2026-09-21

## Version numbering correction

The desktop line is **0.2.x** from this release on. The sequence went `0.1.1`, `0.1.2`, and
then jumped to `1.2.1`, which was a labelling mistake: the intended number was `0.2.1`. The
mapping is therefore `1.2.N ≡ 0.2.N`, and the previous release (`1.2.21`) is `0.2.21` in the
corrected line. The artifacts already emitted keep their original names because the version
*inside* them (bundle `Info.plist`, the UI badge) reads `1.2.x`; renaming the folders would
create a false record. Nothing compares versions internally — `APP_VERSION_INFO` is only
displayed and the data formats carry their own `schemaVersion` — so the correction is safe.

## Clicking a text box starts editing again (the fix could not run before)

1.2.21 added a `pointerdown` handler that claims the window with
`getCurrentWindow().setFocus()` before focusing a field, because WebKit refuses every edit
while the window is not the key one: the caret appears, and typing goes nowhere. Measured in
the packaged app (1.2.21) with the macOS accessibility tree:

- A click **does** focus the field (the focused `AXTextField` changes to the one clicked).
- Keyboard input **does** reach the app when the window is genuinely key (`F1` opened the
  built-in manual).
- `setFocus()` was **never allowed**: `capabilities/default.json` only granted
  `set-always-on-top`, `set-position` and `set-size`, so Tauri rejected the call and the
  rejected promise was swallowed. The fix did nothing at all.

Now `core:window:allow-set-focus` is granted, the window is claimed on **every** click over a
typeable control (not only when `document.hasFocus()` is false, which reads true in the app
even when the window is not key), and a rejection is logged as `window_focus_failed` instead
of vanishing. `test-desktop-ui-contracts.mjs` now cross-checks every window API the frontend
calls against the capability list, so a missing permission can never be silent again.

## HUD alerts: colour flash, no blinking, no entrance animation

`hudStrobe`/`hudPulse` animated `opacity` from 1 down to 0.15 on the alert card and, in
fullscreen, on the overlay itself, so the alert — and with it the whole window — appeared and
disappeared. The flash is now colour, never opacity: the card ring and the title bar pulse
between the urgency colour and its bright variant, and fullscreen washes the screen with an
inset shadow that paints over the overlay background (including a custom colour, which is set
with `!important`). The alert text stays opaque and legible.

The entrance animations (`hudSlideIn`, `hudToastIn`) and the card's transform transition are
gone: an alert now appears fully formed, with only the colour flash.

## Inspector and hover box: every control answers, and the balloon waits

The hint map grew from 77 to 220 entries and the fallback that covers the rest was rewritten:
it reads the real label, says what the control is and what it currently reads, names the block
it belongs to instead of the old "WING CONTROL" placeholder, and humanises the id when there is
no label. The Meter Bridge has the same fallback.

The on-screen balloon now behaves like a static hint: it waits 800 ms of rest before appearing
and leaves as soon as the pointer really moves, instead of appearing after 300 ms and swapping
contents 60 ms after brushing the next control.

## Interface

- **Matrix selector**: families and categories live in a vertical sidebar (like Properties) in
  both windows, so the eleven source families no longer need a horizontal scrollbar. The
  redundant "Jump to" dropdown is gone.
- **Meter Bridge**: groups and banks are a vertical sidebar too (112 px, measured to fit the
  widest label), and the ruler now lines up with the bars (it drifted ~6 px; worst offset is
  1 px, from centring the label on its line).
- **Meters watchlist starts empty**: the fresh-install seed (USB 1-3) is gone in both windows
  and "Reset list" was removed; "Clear" is the only list action and keeps its confirmation.
- **The icon + name block in the header is a label again**: only the logo keeps the pointer,
  the hover, the pressed state and keyboard focus.
